## 一、品牌核心

### 1.1 产品名称

**Tlon** / **特隆**

取自博尔赫斯《特隆、乌克巴尔、第三极的奥比斯·特蒂乌斯》。

**工程解释：** Tlon 是一个多 Agent 协作系统，每个 Agent 运行在独立的 Docker 容器中，通过共享的 Chatroom 进行消息协作。"观念入侵现实"指的是：你用 prompt 定义 Agent 的角色，它在容器中成为可执行的实体，产出真实的代码。

**品牌口号：**
> **"一个开发者，一支军队。一个想法，无限可能。"**
> 
> *One Developer, An Army. One Idea, Infinite Paths.*

## 二、术语体系（博尔赫斯宇宙 + 工程精确）

| 产品概念 | 命名 | 博尔赫斯出处 | 工程含义 |
|---------|------|-------------|---------|
| **产品** | Tlon | 《特隆...》 | 多 Agent 协作系统 |
| **Chatroom** | 代表大会 / Congress | 《代表大会》 | 中央消息总线，所有 Agent 和人类的消息交换场所 |
| **记忆系统** | 莎士比亚 / Shakespeare | 《与莎士比亚的记忆》 | 双层记忆架构：Working Memory（近期交互）+ Episodic Memory（跨会话摘要与事实） |
| **Skill 系统** | 巴别图书馆 / Library of Babel | 《巴别图书馆》 | 符合 Agent Skills 标准的可插拔能力模块，按需激活 |
| **Git 工作流** | 花园 / Garden | 《小径分叉的花园》 | Fork/PR 语义层：分支即平行时间线，合并即可能性交汇 |
| **自举计划** | 环形废墟 / Circular Ruins | 《环形废墟》 | 元编程能力：Agents 开发 Agents，系统自我扩展 |
| **Agent 管理** | Mirror | 《镜子与面具》 | Agent 生命周期管理界面：创建、配置、唤醒、销毁 |

### 术语详解（诗意 + 精确）

#### Tlon
> **诗意：** 一个从观念出发、逐渐入侵现实的宇宙。
> 
> **精确：** 基于 LLM 的多 Agent 协作框架，Agents 通过事件总线通信，在隔离的 Docker 环境中执行代码。

#### 代表大会 / Congress
> **诗意：** 每个 Agent 是思维模式的代表，在协商中为你找到最优路径。
> 
> **精确：** 中央聊天室（Chatroom），所有消息通过 Event Bus 路由，支持 @mentions 机制进行任务分派。客服主动响应，其他角色被动响应（被@时）。

#### 莎士比亚 / Shakespeare
> **诗意：** Agent 拥有的不只是数据，而是"莎士比亚的记忆"——他见过的面孔、摸过的物品、感受过的天气。
> 
> **精确：** 双层记忆系统：
> - **Working Memory**：固定 10 条滚动窗口，存储当前会话的原始交互（含 tool_calls 和 tool_results）
> - **Episodic Memory**：LLM 生成的会话摘要 + 结构化关键事实，持久化存储于 `data/agents/{id}/memory/`

#### 巴别图书馆 / Library of Babel
> **诗意：** 六边形的无限空间，包含所有可能的技能之书。
> 
> **精确：** Skill 系统实现 [Agent Skills](https://github.com/agentskills/agentskills) 标准：
> - **Discovery**：启动时扫描 `skills/` 目录，加载 frontmatter 元数据
> - **Activation**：任务匹配时加载完整 `SKILL.md` 到上下文
> - **Execution**：执行 `scripts/` 或读取 `references/`

#### 花园 / Garden of Forking Paths
> **诗意：** 每一次 fork 都是时间的分叉，PR 是平行宇宙的交汇。
> 
> **精确：** Git 工作流的语义抽象层，将分支/合并操作映射为"路径分叉"与"可能性坍缩"的概念模型。

#### 环形废墟 / Circular Ruins
> **诗意：** 梦中人创造梦中人，创造没有起点。
> 
> **精确：** 元编程与系统自举能力。Agents 可以读取 Tlon 的源代码，修改配置，甚至创建新的 Agent 定义。这是递归的自我扩展。

#### Mirror
> **诗意：** 站在镜前，你决定创造谁。镜中的轮廓既是你的映像，又是即将独立的存在。
> 
> **精确：** Agent 生命周期管理 CLI/GUI。支持：定义角色（position）、配置 LLM 参数、设置 Skills、启动/停止容器、查看状态。

## 四、核心文案（诗意 + 精确）

### 4.1 主品牌文案

**《Tlon 入侵指南》**

```
这不是一个工具。这是一个正在形成的宇宙。

当你输入一个需求，时间分叉了——
产品经理分析需求，项目经理协调资源，
开发者编写代码，运维部署服务。

所有的路径同时展开，又在 @mentions 中汇聚。

[工程层]
Tlon 是一个事件驱动的多 Agent 系统：
- 每个 Agent 运行在独立 Docker 容器
- 通过中央 Event Bus 进行消息路由
- 支持 Tool Use（Bash 执行、消息发送、Skill 激活）
- 双层记忆系统保证上下文连贯

这不是自动化，这是多重意识的共谋。

这是 Tlon。
```

### 4.2 功能文案

#### 代表大会

```
你不再孤独地编码。

在代表大会中，你是主席，也是观察者。
你的 Agents 是代表，代表不同的思维模式，
在协商中为你找到最优路径。

[工程层]
通信协议：
- 消息格式：JSON，含 sender, content, mentions, timestamp
- 路由规则：客服主动响应用户输入，其他角色仅响应 @mentions
- 并发模型：Agent 间并行，Agent 内串行（消息队列）

对话即协作，@mentions 即权力。
```

#### 莎士比亚（记忆系统）

```
每个 Agent 都捧着一本莎士比亚的记忆。

当你第一次告诉它"我喜欢暗色主题"，
那句话成为记忆中永远不会丢失的质感。
第 20 次对话，它翻到那一页说：
"我记得，你喜欢暗色的光。"

[工程层]
记忆系统架构：
┌─────────────────┐
│  System Context │ 角色定义、Skills、工具
├─────────────────┤
│ Episodic Memory │ 最近 5 条摘要 + 10 条事实
├─────────────────┤
│ Working Memory  │ 最近 5 条交互
├─────────────────┤
│ ChatRoom History│ 最近 20 条消息
├─────────────────┤
│ Current Message │ 当前输入
└─────────────────┘

自动触发摘要：
- Working Memory 满 10 条
- 空闲 30 分钟
- 手动 /summary 命令

这不是存储，这是传承。
```

#### 巴别图书馆（Skills）

```
六边形的无限空间，包含所有可能的技能之书。

当你的 Agent 需要处理 PDF，
它走向图书馆的某个六边形，取出一本书——
不是阅读，而是成为。

[工程层]
Skill 目录结构：
skills/
├── git-operations/
│   ├── SKILL.md          # 定义：元数据 + 指令
│   ├── scripts/          # 可执行脚本
│   └── references/       # 参考文档

渐进式加载：
1. Discovery：启动时加载 name + description
2. Activation：任务匹配时加载完整 SKILL.md
3. Execution：按需执行 scripts/ 或读取 references/

激活即掌握，掌握即遗忘边界。
```

#### 花园（Git 工作流）

```
每一次 fork，都是时间的分叉。

在这个分支里，函数以递归书写；
在那个分支里，类以组合生长。

所有可能性同时存在，
直到你发起那个 PR——
让平行宇宙交汇，让最优解坍缩为现实。

[工程层]
Git 语义抽象：
- 分支 = 时间线的分叉（博尔赫斯式时间观）
- 合并 = 可能性的交汇
- 冲突 = 平行世界的不兼容（需要人工裁决）

Tlon 的 Agents 可以直接操作 Git，
但花园层提供了概念模型，
让版本控制成为叙事。
```

#### Mirror（Agent 管理）

```
你站在镜前，决定创造谁。

镜中的轮廓在变化，等待你赋予：
- 一个名字
- 一种性格  
- 一段莎士比亚的记忆

当你说"醒来"，轮廓凝聚，它睁开眼睛。

[工程层]
Agent 配置（YAML）：
```yaml
agents:
  - id: "pm-001"
    name: "林知遥"
    position_id: "project_manager"
    llm:
      model_name: "gpt-4"
      temperature: 0.7
    docker:
      image: "ubuntu:22.04"
      memory_limit: "512m"
    skills: ["plan-i", "git-operations"]
```

生命周期：
1. Mirror 中定义（配置文件）
2. 唤醒（docker run）
3. 活跃（处理消息）
4. 休眠（空闲 30 分钟后 docker stop）
5. 销毁（docker rm + 可选删除记忆）

镜子增殖了现实。
```

## 五、三层营销叙事

### 第一层：个人解放

> **"从孤独编码到指挥交响乐"**

**诗意：** 一个开发者面对空白的 IDE，是孤独的。在 Tlon，你是交响乐团的指挥，每个 Agent 是一种乐器，你在 @mentions 中编织和声。

**精确：** 单开发者可以协调多个专业角色（PM、Dev、Ops）同时工作，通过消息驱动而非等待串行响应。并行化开发流程。

### 第二层：意识的增殖

> **"每一个 Agent 都是你思维的一个分支"**

**诗意：** Mirror 前的创造不是复制，是增殖。你创造的不是工具，而是思维的延伸。他们在代表大会中协商，如同你大脑中不同区域的对话。

**精确：** Agent 继承你的偏好（莎士比亚记忆），但拥有独立的专业判断（Position 定义的行为规则）。他们不是傀儡，而是受约束的协作者。

### 第三层：现实的入侵

> **"观念正在成为现实"**

**诗意：** Tlon 宇宙的本质是观念先于存在。当你的 Agents 产出的代码在服务器上运行，当环形废墟计划让 Agents 开始自我创造——这就是 Tlon 入侵现实的证明。

**精确：** 从 prompt 到可执行代码的完整链条：
```
prompt（观念）
  ↓
Agent 协作（多角色处理）
  ↓
代码生成（git commit）
  ↓
容器执行（docker run）
  ↓
运行中的服务（现实）
```

## 六、界面文案风格指南

### 6.1 双层文案结构

每一条品牌文案都包含两层：
1. **诗意层**（上）：文学隐喻，建立情感连接
2. **精确层**（下/括号内）：技术说明，确保可理解性

### 6.2 用词规范

| 场景 | 诗意用词 | 精确用词（括号内补充） |
|-----|---------|---------------------|
| 系统启动 | "特隆正在入侵现实" | "Tlon Server 启动中，加载 Agent 配置..." |
| Agent 唤醒 | "[林知遥] 从镜中起身" | "正在启动 Docker 容器 pm-001..." |
| 记忆加载 | "莎士比亚的记忆正在苏醒" | "加载 Episodic Memory: 3 条摘要，7 条事实" |
| Skill 激活 | "从巴别图书馆取出一本书" | "激活 Skill: git-operations v1.2.0" |
| 错误提示 | "时间的分叉遇到了阻碍" | "Git 合并冲突：src/main.py 第 42 行" |

### 6.3 避免过度隐喻

**❌ 错误示例：**
```
Agent 在迷宫的深处徘徊，寻找真理的光芒...
（用户不知道发生了什么）
```

**✅ 正确示例：**
```
开发-A 正在分析代码...
[执行：cd /workspace && python analyze.py]

（诗意留给成功时刻，执行过程保持透明）
```
