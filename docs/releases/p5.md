# P5 发布与升级说明

P5 将全部内置原型、Adam 和工作示例切换为 v2 普通模块。旧 stage 引擎和 v1 行为执行已删除，没有兼容执行、自动转换或存储迁移。历史仍可查询和导出；旧 pending 或不可读数据库会阻塞成员，处置步骤见 [实施计划](../design/programmable-workflows-plan.md#p5-实施记录与旧记录处置)。

## 已有实例如何取得新内置包

升级安装包不会覆盖 `~/.tlon/prototypes/` 中已存在的目录。旧内置包的 v1 行为及缺少获批摘要，均不能在本版本实例化；播种也不会向旧包补入新模块。

操作员应先备份和核对本地修改，再将需要更新的旧内置包目录移出 prototypes 到独立归档位置，然后重启 dream，让播种只向空缺位置发布完整新包。保留归档，不直接清库。不建议通配删除 `p-*`，因为同一目录还可能有自定义原型或用户改动。

## 可感知的行为与预算变化

- 内置对话达到 round-limit 会明确失败，随后交由已有宿主失败处理保存证据、向核实过的原人类发件人发稳定通知；不再静默返回成功并标读。已由工具提交的效果仍是真实效果，不会撤销或再次提交。给 Agent 的自动失败信仍不发送，错误可通过运行记录查询。
- 计划后执行最多 10 轮，计划只生成一次。`max_rounds` 是逻辑上限，不保证在共享 fuel、token 或截止时间耗尽前能跑满。P5 发布时 fuel 的硬顶为 10000（当前预算见[原型设计](../design/prototypes.md)），不为计划、核验或嵌套调用赠送预算。回归测试覆盖两种方法各 10 轮、每轮 5 个工具，但更复杂的程序或更大的批次仍可能先耗尽预算。
- arena 对新程序投影的 failed 终态检查已提交 evaluator 的 fuel 耗尽错误，输出 fuel-exhaustion 红旗及序号证据；旧 max_iterations 仅用于历史归档读取。其他失败不会冒充 fuel 耗尽。
- finish-turn 仍是局部纯信号。conversation 函数可在本地合成返回，内置 agent 函数可经普通工具分派取得同一信号；两者都不改变 Agent 调度。根入口返回值才决定调度，用户可编写自己的组合方式。

文档及标准库仍通过 workspace 只读映射查询；没有增加一次性起草调用或专用流程解释器。
