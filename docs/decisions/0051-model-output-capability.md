# ADR 0051：按模型能力与执行资源决定单次输出

日期：2026-10-25
状态：已接受

Tlon 不再配置统一的单次模型输出长度。删除成员 llm.max_tokens 及内置示例中的固定输出上限，使用现有 LiteLLM 模型元数据中的 max_output_tokens。模型能力与上下文窗口随模型配置冻结到 program run；无法解析能力时明确报错，不猜测 4096 等默认值，不增加兼容或迁移。

一次请求的输出额度为模型输出能力、剩余上下文、run 可用预算三者的最小值。剩余上下文由完整请求估算，包含系统提示、消息和工具定义。model-context 与实际请求共用计算规则；仅当没有输出空间时判定上下文不适配，不要求为模型最大输出预留整块窗口。预算耗尽应报告预算错误，不以压缩上下文掩盖。程序对特定调用显式传入 max_tokens 时，仍可进一步收紧该调用。

保留成员 program_token_budget 作为整个 run 的独立共享预算，覆盖行动、规划、自评和压缩。请求前原子预留，成功后按可靠 usage 结算实际消耗并释放差额；output 计 completion_tokens（包含 provider 计入其中的推理消耗），total 计总消耗。缺少可靠 usage 时保留预留额，未知结果不得释放或自动重发；已知拒绝释放预留。真实消耗超过预留也如实入账并阻止后续超预算请求。恢复已提交响应不重复预留或结算。

不同 provider 的省略参数语义不同，部分 API 要求显式输出参数。因此默认采用解析出的模型能力与资源约束生成请求参数，而非一律省略 max_tokens。继续使用现有 LiteLLM 适配，不维护另一份模型能力表。

本决策覆盖 ADR 0048 中 llm.max_tokens 成员上限及成功后不退预留的规则。行动循环工具约束、内部阶段可返回文本、轮数、执行期限和截断失败语义保持。
