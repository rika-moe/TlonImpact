# ADR 0046：以模块函数统一成员工作程序

状态：已接受，P1/P2 已合并（#208/#209），P3 本阶段实现待合并，P4–P5 待实施，2026-10-23。代码基线：`9fe00817bd75944e49a05cfd8e0149fa240dc757`（#198）。ADR 的接受不授权自动施工或合并；各阶段按明确授权独立实施。

设计契约：[可编程工作流程](../design/programmable-workflows.md)。任务范围、验收和删除项：[实施计划](../design/programmable-workflows-plan.md)。本文记录选择与取舍，不将目标描述为已实现。

## 背景

Capability 已由 ADR 0045 删除。当前 tlosure 已支持函数、闭包、有界循环及可暂停宿主调用，ProgramDriver / ProgramStore / OperationExecutor 已支持表达式获得真实效果结果和持久回执。但模型会话仍由 SessionRecipe、固定 stage 注册表、LoopDriver、StageOutcome 和 AgentSession 解释，SessionJournal 另有恢复路径。编写新的工作方式经常仍需扩展 Python 阶段。

目标是让 Agent 编写、导入、调用和复用自己的工作程序，包括模型交互、工具调用、核验与修订；新增工作方式不要求注册新的宿主阶段。

## 决定

1. **Module 组织程序**：tlosure 提供命名空间、显式导入导出、私有函数和不可变常量；模块初始化无外部效果，依赖静态解析。函数使用语言原生值、闭包和高阶组合，不转成复合 Operation，不要求逐函数 JSON Schema 或审批。
2. **Behavior 连接事件入口**：显式声明事件到导出函数的映射。条件和流程写在函数里；导入模块不自动注册处理器。原型继续作为创建与发布程序包的渠道，本决策不改变成员身份或世代政策。
3. **Operation 约束宿主效果**：模型请求、工具分派、状态、邮件和查询统一进入已有宿主执行边界。一个模型契约支持 messages、受控 tools 和完整结构化响应，不自动执行工具。工具批量分派逐叶保存回执，不能用一个非幂等父 intent 遮蔽部分成功。
4. **程序拥有工作状态**：消息列表、草稿、核验结果和迭代计数是显式局部值。Agent 长期状态经领域 Operation 访问；运行预算、调用身份、冻结输入和完成结果属于宿主。模型消息协议、上下文组织与标准工作方式由普通库函数复用。
5. **ProgramStore 是程序恢复权威**：冻结入口程序包及依赖、事件、宿主身份和有效请求输入；重放纯计算，恢复既有外部结果。模块函数不另建预算根或执行日志。SessionJournal 退出新程序恢复，转为可重建的交互查询/投影，保留历史读取及记忆消费者。
6. **完成与调度分离**：子函数返回只结束自身，入口返回结束事件处理。只有入口完成结果可请求成员睡眠或退出；运行完成与调度意图原子提交，调度应用可恢复。模型的局部完成信号不直接结束 Agent。
7. **逐阶段端到端替换**：先跑模块发信，再跑模型核验与工具循环，再迁移标准工作方式和会话消费者，最后排空旧工作并删除 stage 引擎。建设期按明确入口选择路径，无失败回旧路径、旧格式转换或存储迁移。

## 备选

- 自定义 stage：可复用现有会话引擎，但保留 session/scratch/Outcome 协议和嵌套流程限制，不满足普通程序组合目标。
- 状态图作为主程序：便于显示分支和人工介入，但为循环、函数与动态组合增加另一套语言；可视化应先从运行轨迹派生。
- 直接迁移 Temporal / LangGraph 等执行框架：成熟持久执行值得参考，但若不能替代整块执行基础设施，会与现有回执、预算、调度形成双重权威。本轮不引入新引擎；若实施发现现有基础无法满足契约，回到 ADR 比较证据，不能静默增加第二执行器。

## 后果与边界

工作程序统一为函数，代价是必须补齐模块快照、完整模型请求、错误分类、恢复和交互投影。批准代码不授予调用者权限；新效果仍检查当前领域权限与撤销状态。历史成功不是重新执行，不重复扣费。

本次不恢复 Capability，不新增逐函数发布体系，不提供宏/eval/任意 FFI、动态模块加载、DSL 并发、模块函数 Tool 投影或任意事件的长时间 await；不改变 Agent 身份升级和世代模型，不实现动态工具视图。现有工具并发由宿主受控分派维护。

## 修订关系

本决策保留 ADR 0018 的包方向、ADR 0021 的函数能力、ADR 0043 的可返回结果程序及 ADR 0045 的删除决定。实施完成后替代 ADR 0004 的 stage 扩展机制、ADR 0042 的旧规则/配方编排边界；ADR 0007/0009/0032 的历史交互记录保留，新运行恢复与交互权威按本决策划分。上述文档在对应实施阶段注明实际切换状态，不提前宣布旧机制已删除。

## 实施记录：P2

完整模型操作已替换 prompt-only 输入，返回包含可空 content、规范化工具建议与 reasoning_content 的响应。纯 tlon.messages 支持函数组合；生成、核验、修订示例不注册 stage。宿主系统输入、工具契约及有效模型配置在 v2 受理时冻结，模型已提交但外层回执缺失可只读恢复并补回执。旧阶段复用相同 ModelService，stage 删除仍在 P5；工具执行与可复用对话循环仍待 P3。阶段验收证据见实施 PR 与 #202，本文不提前宣称后续阶段已完成。

## 实施记录：P3

普通对话模块与 tool-execute 编排端口已实现，叶子回执继续由 ProgramStore/OperationExecutor 负责。消息关联、有限轮循环和局部完成留在普通函数；宿主保留授权、错误分类和恢复。当前分派按声明顺序逐叶执行，不新增并发语法；共享工具边界不再把未知效果和基础设施故障伪装成模型可修正失败。阶段证据见 #203 与实施 PR，旧 stage 和交互消费者继续按 P4/P5 计划保留。
