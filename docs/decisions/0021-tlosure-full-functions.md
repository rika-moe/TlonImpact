# ADR 0021：tlosure 完整函数能力——defn / 闭包 / 变长参数 / 递归 / 一等函数

> 阅读定位：本文保留当时的选择与理由；当前设计见 [dsl](../design/dsl.md)、[bridge-api](../design/bridge-api.md)。当前适用范围：完整函数能力；替代旧的无定义能力及动作位置可枚举保证。完整关系见 [决策索引](README.md)。

状态：已接受（2026-09-28，方向讨论拍板）

## 背景

EPIC #44 的 defn 评估：初议（主会话建议）是受限形态——只允许顶层定义、只允许纯函数、固定元数、禁递归、函数不是值，理由是 dsl.md 记录的两条论证（递归使终止性更依赖 fuel；函数值破坏"加载时行为可枚举"）。拍板结果是**不做受限形态，直接上完整能力**：

- `defn` 可在各处定义（不限顶层）；
- 函数体可含副作用词汇（动作 builtin）；
- 变长参数；
- 允许递归；
- 一等函数（函数作为参数与值，闭包捕获环境）；
- 总原则：**尽可能不限制语言能力，agent 的消耗统一由 fuel（+ 深度顶）约束**。

## 决策

### 1. 语言获得完整函数能力

`defn`（任意 body 位置定义命名函数）、`fn`（匿名函数）、闭包（捕获定义时环境）、变长参数（`[a b & rest]`）、递归（名字在定义体内可见）、一等函数（函数是可传递、可返回的值）。函数应用与普通 builtin 调用同构计费：每次求值步计 fuel，嵌套调用计深度。

### 2. 能力约束的四个保留杠杆

函数能力扩张后，信任模型从「静态可枚举性」后退到以下四道仍成立的闸：

1. **fuel + 深度顶**：任何求值必然终止且代价有界——递归再深也撞 `MAX_DEPTH`、步数再 wild 也撞 `MAX_FUEL`。这是拍板指定的主杠杆。
2. **effects-as-data 不变**：动作 builtin 在函数体内被调用时，产出的仍是 `ActionRequest` **数据**，由引擎在求值结束后执行；spawn 预算、信任闸等执行侧检查不可绕过。"DSL 描述，引擎执行"这条架构不动。
3. **语境注册表不变**：动作词汇只在成员注册表语境可见——`:when` 门控、`:until`、stage `:if` 的注册表里没有动作词，函数体里写了也在加载期被拒。词汇级分区保留。
4. **staging + 人工批准不变**：LLM 撰写的 spec 仍走信任闸。

### 3. 被放弃的保证（如实记录）

- **动作位置的语法纯度分区弱化**：`validate_member_action` 的「包装形式只允许 `when`/`while`/`map`、参数必须纯表达式」在函数调用面前失去静态可判定性——函数体可以藏动作。~~该门禁对直接动作形式继续生效~~（施工注记：tlon 集成时进一步拍板为**整体删除**——`validate_member_actions` 只做全量注册表校验 + `defn` 跨 form 穿线，对直接动作形式也不再保留分区），但"加载时枚举全部动作点"不再是系统性质；运行时 collector（on-complete 路径）与返回值收集（规则路径）是动作汇聚的实际机制。
- **控制流加载时可枚举**：被「加载时可静态校验 + 运行时有界」替代。

### 4. 不变量（本次不动）

无 `eval`、无宏、无可变全局状态（defn 绑定在词法环境，环境随求值结束消亡）、无并发原语。~~`map`/`filter`/`reduce` 的显式绑定形式保留不变。~~ 2026-10-30 修订：三者改为普通高阶函数，见下节。

## 后果

- tlosure 从「规则描述语言」升级为「受限宿主资源下的通用语言」；这是 dsl.md 信任模型的一次重大修订（相应章节同步改写，废止段删除线保留）。
- `tlosure/eval.py` 与 `tlosure/validate.py` 镜像扩展（闭包值、defn/fn 特殊形式、应用规则、作用域与元数检查）；`validate_member_action` 的分区语义弱化并在文档中如实标注（施工注记：tlon 集成落地为 `validate_member_actions`——分区删除，序列级全量注册表校验 + defn 穿线）。
- 生成文档（tlosure-reference）列出新的特殊形式与语义；spec 作者（含 LLM）获得抽象能力，spec 重复片段可收敛。
- 风险与缓解：深层递归/spec 复杂度上限由 fuel/depth 兜底；动作藏匿的可审计性损失由 staging 审批与运行时 ActionRequest 日志（执行侧可观测）补偿。
- ADR 0011（SCI 兼容子集）：函数能力的语义选择应向 SCI/Clojure 看齐（`defn`/`fn`/变长的形状），为未来迁移留路。

## 2026-10-30 修订：集合操作使用普通高阶函数

状态：已接受（2026-10-30）。

采用 Lisp/Clojure 的函数参数模式：`(map f coll)`、`(filter pred coll)`、`(reduce f init coll)`。保持当前向量输入、立即求值、向量输出、filter 使用现有真值规则、reduce 显式初值，不增加惰性序列、多集合或无初值重载。删除旧显式绑定语法与校验分支，不保留兼容层。

注册表函数成为可求值、传参、返回和局部绑定的函数值，支持 `(map inc xs)`、`(reduce + 0 xs)` 以及 `(let [f map] (f inc xs))`。局部绑定优先于注册表；特殊形式仍是语法，不能当函数值使用。函数值保存原注册表名字，使别名调用副作用函数时仍使用原操作标识。

实现复用现有生成器求值内核：集合 builtin 对每个元素产出通用函数调用请求，由求值器统一调用闭包或注册表函数。集合循环及追加结果保持线性，不用反复 conj 拷贝实现 map。通用调用路径不按 map/filter/reduce 名字分支；所有实参先正常求值，回调继续共享 fuel、深度、同步/异步效果暂停与恢复。每次回调应用必须计费，包括直接调用宿主 builtin；空集合也校验回调是函数和集合类型。

高阶函数本身不引入外部效果，但回调可能有；不得把其 pure 标记解释成可以跳过回调的效果调度。回调异常、取消及 recur 函数边界按普通函数处理。

同步修改内置程序、示例、测试和语言文档。本 ADR 原保留显式绑定形式的条款废止。用户磁盘上自定义旧源码需显式改写，不提供迁移或 fallback。冻结的旧 run 源码同样不自动改写；升级不得假定旧语法程序可在新内核中继续重放。

参考：[Clojure core API](https://clojure.github.io/clojure/clojure.core-api.html)（map/filter/reduce）。仅借鉴函数参数接口，不声称实现 Clojure 的惰性或多元调用语义。
