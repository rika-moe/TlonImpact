# ADR 0025：mail-history 两段式——冻结段 + 滑动段

> 阅读定位：本文保留当时的选择与理由；当前设计见 [runtime](../design/runtime.md)。当前适用范围：Mail-history 冻结段与滑动段。完整关系见 [决策索引](README.md)。

状态：已接受（2026-10-07 拍板；EPIC #124）

## 背景

ADR 0015 落地后，会话内前缀逐字节稳定（journal 证明纯尾部追加），但跨会话复用有一个已知断点被明确挂起：「mail-history 窗口滑动不优化——>N 封后丢弃最老邮件会断前缀……留待度量数据证明值得后再议」。

度量数据现已齐备（2026-10-05 ~ 10-07 ledger，854 次 LLM 调用，33.4M prompt tokens，整体命中 66.5%，纯追加理论上限 85.3%）：

- 139 次会话首次调用的 prompt 合计 2.7M tokens，只命中 1.1M（~41%），差距 ~1.6M 的主因就是窗口滑动：每来一封新邮件，「最近 20 封」整体平移，锚点内 mail-history 段从第一条起逐字节失效，其后的 thread-recap、当前邮件全部按未命中计费。
- 差距的其余部分（~4.6M）是 DeepSeek 服务端缓存波动（prompt 单调增长而命中秒级归零又恢复），客户端不可控——不在本决策范围。

## 决策

1. **DSL 形式扩展**：`(mail-history N)` 保持现有语义（最近 N 封滑动窗口），继续合法；新增 `(mail-history F R)` 两段式——**冻结段 = 邮箱最早 F 封（写满后逐字节稳定、永不再变）+ 滑动段 = 最近 R 封**，总量不足 F+R 时重叠部分去重只渲染一次。参数均为非负 int，渲染顺序保持时间正序（冻结段在前、滑动段在后），~~当前邮件仍由引擎追加在最后，语义不变。~~（ADR 0028：触发邮件本体不再注入，改为固定模板触发语「你有 N 封未读邮件」由引擎追加在最后。）
2. **内置原型切换**：9 个认知型原型（support / product / pm / ops / developer / data-analyst / scribe / deep-thinker / archivist）`(mail-history 20)` → `(mail-history 20 10)`；fast-responder 的 `(mail-history 5)` 不动（锚点小，无收益）。
3. **既有成员不强制迁移**：`(mail-history N)` 是合法 spec 而非兼容层，老成员配置照常加载；新成员按新原型生效。
4. **排序原则不变**（ADR 0015）：冻结段的加入让 mail-history 内部的前段变为「几乎不变」，整体段在 sections 向量中的位置不动。

## 否决的备选

- **per-thread 历史**（ADR 0015 提过的另一个方向）：线程按首封信排序后线程内追加虽稳定，但跨线程插入仍断后缀，且把「我最近处理过什么」的时间序视图换成分组视图，行为变更更大；两段式用更小的语义变化拿到同量级收益。
- **步进重冻结**（冻结段按步长 S 定期重写为更大集合）：冻结点每次前进都全段重写断一次前缀，实现与推理复杂度高于「最早 F 封永久冻结」，增量收益不成比例。
- **纯缩窗口（20→10）**：断裂体积减半但召回历史同步减半；两段式在改善缓存的同时召回跨度反而变大（最早 F + 最近 R，有界 ≤F+R 封）。

## 后果

- 冻结段写满后，新邮件的缓存断裂区域从 20 封缩到 R=10 封，首次调用命中率预期显著上升（效果以 ledger 度量为准：首调命中率、每 session 平均 prompt、整体 cached/prompt 三项对比）。
- 成员的「创世记忆」（最早 F 封，通常是 onboarding 与人格确立期的往来）永久驻留锚点——锚点有界（≤F+R 封），context pressure 的锚点语义（ADR 0008/0017）不受影响。
- `Mailbox` 需支持按时间正序取「最早 F 封」（现有 `recent()` 只支持尾部窗口）。
- `docs/reference/dsl-reference.md` 5.1 节语义表与排序原则段同步更新。
