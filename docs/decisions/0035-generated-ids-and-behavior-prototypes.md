# ADR 0035：系统生成标识与行为化原型库

> P3c 当前实现：宿主能力统一定义为 Operation；Tool 与 DSL 共用定义和执行边界。旧工具名和类名仅记录当时设计，当前入口见 [工具手册](../reference/tools-reference.md)。
- 状态：已采纳（2026-10-17）
- 修订：ADR 0006 的行为原型呈现、ADR 0024 的身份边界；不改变成员自主社会身份。
- 后续修订：[ADR 0038](0038-distinct-behavior-prototypes.md) 调整内置行为清单，保留 8 个原型；本文合并清单保留为当时的决策记录。

## 决策

原型的稳定技术标识由系统生成，格式 `p-<uuid4 hex>`；现有 `name` 字段承担标识，不增加平行 ID 层。trusted／staging 创建函数、writePrototype／proposeBehavior、REST／WebUI 创建不再允许调用方指定 name，旧输入明确拒绝，无别名或职业名映射。显示名 display_name 为必填的非空行为标签，创建者描述触发条件、处理过程、上下文、预算、执行能力或反思节奏，不用职业头衔代替行为差异。description、proposal_note、评审指引同样区分行为与社会身份。保留业务任务意图，不设职业词黑名单，也不新增 LLM 命名审批调用。

普通新成员通过管理创建与 spawn 创建时，系统生成 `m-<uuid4 hex>`，不嵌入 prototype、职业或显示名。成员创建 API 不接受 agent_id，仍允许指定成员显示名与人格种子；原型不负责赋予职业。内部 instantiate 是将系统已分配 ID 落盘的私有装配操作，仍接收系统传入的 ID；arena 的隔离成员使用系统生成的 run-id，内置 Adam、系统 postmaster 和单人 WebUI 的人类地址不重编号。ID 分配、碰撞与现有 WebUI 地址冲突检查须在写入前完成，不能因随机化取消地址唯一性约束。

原型的 parent、谱系、评审、批准和 spawn 引用使用生成的原型 ID。内置原型的 ID 在源码中一次生成并固定，启动播种复用同一 ID，不能每次启动创建一套新血脉。新提案 ID 在校验通过后分配并持久化；失败不留下空原型。去掉 name／agent_id 的表单及工具参数，不保留旧参数 fallback。

## 内置库清理

解析现有 behavior.tlon 的 EDN 后比较结构，忽略注释与空白；有参数的模板保持其完整声明语义。确认 developer 与 data-analyst 行为相同，pm 与 product 行为相同，各合并一份。11 个原型保留 9 个行为不同的原型：频繁反思迭代、长预算工具迭代、超长预算迭代、精简上下文响应、标准工具迭代、标准文件迭代、定址转发、低频反思迭代、标准无执行迭代。按实际执行层级／上下文／反思周期／预算写描述，不声称代码未实现的专业倾向；不为去职业化删除已有行为差异或能力。

`listPrototypes` 不再称原型为「人格模板」。公共协议、原型编写／评审工具与文档明确：原型只描述怎样行动，不认证谁是什么人。派生者的社会身份由其自主表达与交往形成；同一原型可承担不同工作，同一工作可使用不同原型。

## 存量与范围

不提供旧原型名称别名、参数兼容或迁移脚本。不删除或改写用户已有 ~/.tlon 中的原型、成员、人格、记忆、谱系和邮箱；它们是持久数据，不是包内旧名字的兼容映射。既有成员已持有行为副本，不因包内原型整理被重建。新内置库播种继续不覆盖用户文件；旧库清理由用户对具体实例另行决定。源代码、测试和当前文档改用生成标识／行为显示名，不再以职业名寻址内置库。旧 TUI／SDK／Telegram 不恢复可用性。

## 验证

覆盖 trusted／staging 创建、编辑与谱系、writePrototype／proposeBehavior、管理成员创建与 spawn 的系统 ID、旧字段拒绝、必填行为显示名、ID 无职业片段、失败不写盘、地址冲突仍有效；内置库 9 份语义唯一且播种幂等；WebUI 不再填写技术 ID。全量 scripts/check_all.sh，隔离 dream 实测创建原型、创建成员、发信入箱，清理进程与临时数据。
