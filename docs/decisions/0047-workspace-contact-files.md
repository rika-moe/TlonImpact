# ADR 0047：私人资料通过普通 workspace 文件访问

状态：已接受，已实现。

## 决定

CONTACTS.md 是 Agent 自己维护的普通文件，唯一位置为其持久 workspace（宿主 `~/.tlon/{id}/workspace/CONTACTS.md`，程序侧使用工作目录下的 `CONTACTS.md`）。不迁移或回读旧 config/CONTACTS.md，不保留副本、同步或旧操作别名。初始社会直接在新位置播种联系人资料。

系统提示只保留固定说明：联系簿是主观、私有、可修正的笔记，按需通过 file-read 读取，使用 file-edit/file-write 更新；不存在时可创建。公开地址仍由 member-list 提供。联系人全文不进入 system prompt，也不参与人格提示词的变更签名。程序不被框架强制逐轮读取联系人。

L0/L1/L2 均可通过现有五个文件 Operation 读、写、局部编辑、列出和搜索自己的持久 workspace，无需 Docker。宿主显式绑定成员 workspace，调用参数只使用逻辑工作目录路径，不能指定其他成员或宿主数据根。Docker 与 Shell 仍由现行等级控制；workspace 之外的装置访问保留既有约束。文档与标准库映射保持只读，/tlon-home 不新增写权限。

普通文件访问必须拒绝路径逃逸、通过符号链接访问宿主或其他成员、以及写入只读作者材料。宿主文件访问不能只做字符串前缀检查或检查后无约束地重开路径。所有调用仍通过 OperationExecutor 的身份、校验、预算和持久回执；读回执重放返回原值，写结果未知不自动重发。

删除 contacts-read、contacts-upsert、ContactService 与联系人专用解析和格式维护。格式由 Agent 自己组织；局部修改使用 file-edit，框架不承诺按联系人保留条目。persona-update 与人格文件权限保持原有职责。

## 原因与取舍

按需读取避免联系人变化修改长系统前缀，减少无关上下文，并复用已有文件操作而非继续增加领域工具。代价是 Agent 必须主动读取、组织和更新自己的资料；联系簿的存在不保证每次调用都会使用它。不能用缓存命中百分比替代任务质量和实际输入成本。

## 实施与验收

先同步本决策和当前设计，再实现：workspace 文件访问；联系人位置、播种与提示说明；删除专用服务/操作；更新 reference、测试和打包说明。验收覆盖三个等级无 Docker 的五项文件操作、成员隔离、路径/链接与只读边界、联系人改动不改变系统提示、跨请求读取最新内容及持久回放不重读。运行完整 scripts/check_all.sh；隔离 TLON_HOME 启动真实 dream，经 SDK 和真实模型完成按需读写联系人、回信，并核对宿主文件与 SQLite 收件箱。PR 记录实际结果，先不合并。

## 实现验证

完整质量门 14/14：单元 2462 passed / 15 skipped，集成 44 passed。覆盖三个等级、默认/自定义/根工作目录、未绑定拒绝、路径/链接/只读边界、写入时目标替换，以及磁盘回执重放。

隔离 dream + SDK + 真实 DeepSeek 的标准 L0 原型完成两次邮件任务：首次 file-read → file-edit → file-read（5 次模型调用），更新文件后再次真实读取（3 次模型调用），各一封持久收件箱回信。两个入口冻结的 system prompt 哈希相同且不含联系人正文；服务和临时目录清理完成。该证据验证提示前缀稳定性，不代表整体缓存命中率已有量化提升。

首轮冒烟模型自行发信与外层回信重复，未通过单封回信断言；明确冒烟任务由外层发送后重跑通过。此处没有修改现有标准程序的工具集或邮件完成策略。
