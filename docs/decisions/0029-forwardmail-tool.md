# ADR 0029：按邮箱引用转发邮件

状态：已接受（2026-10-16）；投递结果契约由 ADR 0030 修订，执行格式与适用范围由 [ADR 0042](0042-unified-member-rule-execution.md) 修订。当前实现见 [mail](../design/mail.md)。

## 保留的决策

1. `forwardMail` 工具显式接收自己邮箱中的 `mail_id`，以及 `to`、可选 `cc`、可选 `comment`。模型可以先查邮箱，再选择来源；工具不负责结束会话。
2. 引擎在真实执行时校验来源属于当前成员邮箱，防止引用不存在或不可见的邮件。取得邮局回执后才返回真实工具结果；拒绝或未知直接返回，不制造 postmaster 退信。
3. 转发正文包含评语与来源头（发件人、日期、主题、原正文），收件人无需原上下文即可理解。外部来信保留不可信内容标记，转发不能洗去信任边界。
4. 转发另起线程，`forward_of` 保留来源链接；不继承原信的回复链。

## 后续修订

ADR 0042 删除了按规则形式限制转发的设计。DSL `forward` 使用当前规则保留的原始触发邮件；模型工具 `forwardMail` 显式选择邮箱记录。两者可在同一成员程序中组合，包括先运行会话、再转发来源邮件。

旧的规则类别检查与“执行会话后不能使用 forward”限制已删除。邮局引用校验、来源归因、线程选择和真实回执契约继续保留。
