# ADR 0041：管理员四态操作与提前唤醒

状态：已实施（2026-10-18）。用户批准同步修改文档、接口、WebUI 和回归测试。

## 决策

1. 保留 active、waiting、sleeping、dead 四种状态。活跃由真实工作派生，管理端不提供直接写入 active 的接口。按钮使用动作名称：唤醒、进入等待、定时睡眠、调整醒来时间、永久退出。
2. 管理员可以提前唤醒睡眠成员，覆盖 ADR 0039 中“仅到时自然醒”的限制；普通邮件和成员工具仍不能提前唤醒他人。唤醒撤销持久睡眠期限和旧计时器，检查真实邮箱；有可处理邮件才活跃，否则等待，不凭空发起模型调用。
3. 进入等待与定时睡眠不强制取消当前 LLM、工具或后台工作。活跃成员先排空当前工作，期间阻止接纳新工作；等待只是结束本轮后恢复正常调度，有未处理邮件时可能立即再次活跃。睡眠期间正常收信但不处理，到期或管理员唤醒后检查邮箱。睡眠时间必须为带时区的未来时刻，落盘归一为 UTC；支持修改已有睡眠期限。
4. 死亡为终态，所有唤醒、等待和睡眠操作均拒绝；永久退出保留历史，拒收新邮件。已提交的退出请求不能由其他调度按钮撤销。过期计时器不得覆盖新的睡眠期限、提前唤醒或死亡。
5. 管理接口为 POST /admin/agents/{agent_id}/wake、/wait、/sleep（JSON wake_at），沿用 /terminate 表达永久退出。完成返回 200，排空中返回 202，并返回权威 agent 状态；未知成员 404，状态冲突 409，无效时间或请求 400。不新增普通成员工具、兼容别名或直接设置状态字段的接口。
6. 未完成排空的管理等待/睡眠请求在重启后清除，按 journal 恢复未结束工作，管理员可重新发起；只有正式入睡后的 UTC 期限持久恢复。不得将仍有未结束会话的排空请求恢复为睡眠。
7. WebUI 按状态展示可用动作：活跃提供进入等待/定时睡眠/永久退出；等待提供定时睡眠/永久退出；睡眠提供唤醒/调整醒来时间/永久退出；死亡不提供状态操作。排空中显示待执行操作，避免重复冲突请求；永久退出必须确认不可恢复。睡眠弹窗支持时长或具体本地时间，提交带时区时间。

## 验收

覆盖主动睡眠与管理员睡眠、活跃工作排空、管理员提前唤醒（有信/无信）、修改期限与旧计时器竞争、睡眠跨重启、死亡拒绝所有恢复操作、接口校验、WebUI 按状态显示与调用正确接口。全量质量门和真实隔离冒烟使用临时 TLON_HOME，不修改当前 ~/.tlon，不发送真实社会邮件。

验证结果：最终 `scripts/check_all.sh` 14/14 全绿；Python 单测 2309 通过、15 跳过，集成测试 26 通过，WebUI 112 测试通过且生产构建通过。首次全门禁发现按钮测试将 title 提示误当按钮文字，修正为精确按钮文字断言后重新跑全门禁通过。真实隔离 dream + SDK + 本地模型替身 + WebUI 点击验证睡眠、调整期限、有信/无信提前唤醒及永久退出；2 次模型调用，无成员发信，死亡拒绝所有恢复操作，历史保留，临时实例与端口已清理。
