# ADR 0037：动态工作方式与长期行动习惯（远期目标）

状态：方向已接受，实施延期（2026-10-18）。本文记录远期目标，不表示当前 DSL 已支持动态上下文或成员自改流程。

跟踪：[GitHub Issue #173](https://github.com/rika-moe/TlonImpact/issues/173)。

## 背景

当前 prototype 在实例化时将完整 behavior.tlon 拷贝给成员，成员以相对稳定的流程运行。长期希望成员既能按任务自主选择工作方式，又能从经验中形成自己的行动习惯。近期先改进稳定原型，见 ADR 0038。

## 方向

1. 系统边界、prototype、长期习惯和当前工作方案分别负责权限与资源上限、初始方法、条件化的经验偏好、本次任务的上下文与迭代选择。
2. 成员可在受限 DSL 中选择或调整上下文配方：相关历史、检索内容、摘要、计划和工作笔记；可按需选择规划与评审阶段。不直接改写原始 journal，也不能删掉必需协议或 RULES 来改变权限。
3. 优先复用现有上下文构件、stage 和 lessons。命名工作模式是可组合配方，不预设职业，不建立封闭的模式枚举。
4. 初次思考时选择方案，遇到信息缺口、连续失败或任务变化时再调整；不强制每轮增加一次模式分类 LLM 调用。切换不重置累计预算，不提升工具权限。
5. 会话记录方案、调整理由及可观测结果；周期性反思形成带适用条件的偏好。模型自评不能独自证明交付有效；运行结果、来源和用户反馈分别保留其证据强度。

## 实施前必须确定

- 可修改 DSL 的具体子集与结构校验，哪些上下文必须保留。
- 工具结果收齐后的方案切换点、上下文重建与压缩锚点关系，确保调用与结果配对。
- 方案与习惯的存储及事件溯源，如何复用 lessons，避免重复事实源。
- 预算计量、故障处理、无有效证据时的偏好更新政策及评估任务。

## 近期边界

本轮不实现运行中切换、成员自改 behavior.tlon、自动更新长期习惯或新增权限。保持原型冻结拷贝与现有审批流程；已有实例不自动重写。
