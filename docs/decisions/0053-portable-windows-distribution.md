# ADR 0053：Windows 完全便携发行版

日期：2026-10-30
状态：已接受并实施；发行包自动验收见 CI，Windows 10/11 干净实机验收待完成

## 背景

目标用户是没有 Python、uv 或 Docker 的 Windows 普通用户。现有服务端已托管 WebUI，文件锁、生命周期和 workspace 的 Windows 适配已经合并，但开发环境与托管 Windows CI 通过不代表发行包或 Windows 10 实机验收通过。

用户明确选择「程序和所有数据都在一个文件夹里」。发行方式采用下载 ZIP、解压、双击启动，不要求安装器、管理员权限或系统级 Python。安装器和将数据保存在用户目录的免安装方案不作为本发行版的实现方向。

## 决策

### 发行目录与数据归属

```text
Tlon/
├─ Tlon.exe       # 用户启动入口
├─ runtime/       # 随包提供的 Python、依赖、WebUI 与内置资源
└─ data/          # 首次启动创建，后续升级保留
   ├─ .env        # API Key 等配置
   └─ ...         # 身份、成员、邮件、workspace、日志及运行状态
```

这是发行目录的职责划分，不要求把所有依赖压成单个 EXE。用户机器不需要 Python、uv、Node 或 Docker；构建机负责收集运行时、依赖、前端产物及内置资源。Docker 保持可选，不可用时不注册 Shell，已有 workspace 文件能力继续可用。

便携入口以自身可执行文件所在目录确定根目录，与当前工作目录无关；显式构造 `TlonPaths(home=<发行目录>/data)` 并贯穿各层。该入口不读取原有 `~/.tlon`，不受外部 `TLON_HOME` 重定向，不自动导入旧实例，也不增加路径兼容或迁移层。现有开发者 CLI 的路径约定不变，两者是明确的入口契约。

Tlon 管理的持久配置、业务数据、日志、缓存及实例控制状态均属于 `data/`；程序资源属于 `runtime/`。不得在目录不可写时悄悄改写用户目录或其他磁盘。第三方依赖的持久缓存位置也必须纳入打包验收。

第一版面向 Windows 10/11 x64，运行位置限定为可写的固定本地磁盘，并继续遵守 workspace 的链接与路径边界。不承诺从 U 盘、UNC 或映射网络盘直接运行。检测到不支持的位置或权限时，应明确解释原因并停止启动。

### 启动与退出

1. 双击 `Tlon.exe`，展示启动状态，启动本地服务；确认服务及 WebUI 就绪后，才打开默认浏览器，不用固定延时猜测就绪。
2. 同一数据目录只允许一个运行实例。再次双击打开已有实例，不重复启动服务；仅凭端口有响应不能认定是自己的实例。
3. 服务仅监听本机回环地址，延续 ADR 0033 的身份与浏览器来源边界。端口冲突由启动流程处理，不要求普通用户修改端口，也不终止占用端口的其他程序。
4. 关闭浏览器不停止服务，成员与定时任务继续运行；托盘显示运行状态，提供「打开 Tlon」「打开日志目录」「退出 Tlon」。第一版不自动注册开机启动。
5. 托盘退出触发正常关闭，停止组件并释放端口及实例锁。无控制台入口必须有明确的停止通知机制，不能依赖用户发送控制台信号。
6. 启动失败必须显示可读错误及日志入口；不得留下不可管理的后台服务。浏览器未能打开时，应显示实际访问地址供用户手动打开。

启动入口负责实例管理、启动反馈、托盘和浏览器操作；服务端继续负责 runtime、REST/SSE 和 WebUI。具体使用单进程还是受控子进程，不在本 ADR 中预先规定。

### 首次使用

在 WebUI 完成实例名字、模型服务商、API Key 的配置与连接验证，不要求用户编辑 `.env`。模型仍按 ADR 0016 属于成员配置，向导不得引入新的进程级统一模型设置；初始成员所需模型的选择与生效必须纳入首次使用闭环。

API Key 等本地配置保存在 `data/`，不进入发行包、不写入日志。完整复制该目录会同时复制这些凭据；页面与备份说明应明确这一点，不宣称本地配置文件是加密保险库。

### 移动、备份、升级与删除

- 移动或备份前先从托盘退出，待正常关闭后复制整个文件夹，避免把正在写入的数据库当作一致备份。
- 支持将完整目录复制到另一台受支持 Windows 电脑的固定本地磁盘，再双击继续使用。Tlon 自有持久状态不得依赖原安装绝对路径；用户自行填写的外部路径或外部服务依赖不自动变成便携资源。
- 第一版手动升级：退出后替换 `Tlon.exe` 与完整 `runtime/`，保留 `data/`。更新包不附带用户 `data/`，不得通过清空或重新播种覆盖已有实例。此规则不构成任意版本的数据兼容或降级承诺；不兼容版本须在发布说明中明确，不增加隐式迁移层。
- 删除整个文件夹即删除程序和 Tlon 管理的全部数据，不注册系统服务，不要求卸载程序。

「所有数据在一起」限定于 Tlon 管理的文件。默认浏览器的历史、缓存，以及操作系统自身的记录不由 Tlon 控制；完全便携不等于系统无痕。依赖外部模型服务也不等于离线运行。

## 取舍与实施边界

采用浏览器界面复用现有 WebUI，避免为发行引入另一套业务 UI。文件夹发行使程序资源与用户数据的边界明确，代价是用户必须保留完整目录，并在升级时正确保留 `data/`。

实施采用 PyInstaller 目录模式，在 Windows x64 / Python 3.13 上原生构建；工具版本由锁定依赖管理，CI 检查资源完整性并运行冻结 EXE。不引入安装器、自动更新系统、Windows 系统服务或内嵌浏览器。设计依据与先前平台适配见 [Windows 原生运行适配](../design/windows-support.md)。

## 验收要求

- 在没有 Python、uv、Node 和 Docker 的干净 Windows 10/11 x64 环境解压发行包，完成首次配置、真实模型回信及持久邮件检查；托管 Windows Server CI 不能替代该验收。
- 验证中文与空格路径、不同启动工作目录、外部 `TLON_HOME`、已有 `~/.tlon`、只读目录、不支持的磁盘、端口冲突、连续双击和启动失败。确认不会串用实例数据、写入其他持久目录或留下后台进程。
- 验证关闭浏览器后继续工作、托盘重开页面及正常退出、重新启动、服务异常退出后的再次启动，检查端口和实例锁释放。
- 退出后将整个目录搬到另一位置和另一台受支持电脑，验证身份、成员、邮件、配置与 workspace 保留；替换程序资源升级后验证 `data/` 未被覆盖。
- 验证运行时依赖、原型、技能、文档和 WebUI 资源完整，Docker 缺失时文件工具正常且 Shell 不注册，浏览器来源与 workspace 安全约束保持有效。
- 代码实施执行 `scripts/check_all.sh` 及真实 dream + SDK 邮件冒烟；发行包另做上述端到端验收，不以源码测试通过代替打包结果。
