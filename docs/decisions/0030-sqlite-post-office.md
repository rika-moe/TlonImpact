# ADR 0030：SQLite 邮局与明确的投信契约

日期：2026-10-16。状态：已实施。

## 决策

投信、入箱、阅读/思考是不同语义。本地投信与全部本地入箱在一个 SQLite 事务内完成；返回成功表示本地已入箱，不表示已读或工作完成。EventBus 仅通知已提交的事实，不运输唯一的业务副本。

`to`、`cc` 全部解析和验证，任一地址无效或成员已退休则整封拒绝，列出全部问题，不产生成功记录或另发退信。休眠/离线成员正常收信；退休成员拒收新信，历史可查。退休标记和入箱通过数据库写事务排序。重复地址只入箱一次，允许自寄。

邮件正文不可变且仅保存一份；发件箱与收件箱通过发件人、邮箱归属查询。已读由收件人显式标记，查看和开启 session 不自动标读；不提供发件人已读回执，不记录思考/任务进度。

稳定的 `request_id` 按发件人去重：同键同内容返回已有结果，同键不同内容拒绝。超时是结果未知，使用原键确认；重放不得重新投本地信或自动重复外部操作。

已注册网关允许作为地址，但只承诺尝试投递网关信箱，不保证成功或外部平台接收。尝试独立于本地事务，失败不撤销本地入箱。记录成功/失败/未知；崩溃留下的未知结果不自动重试。没有持久化 outbox 或后台可靠外发队列。

新数据库位于 runtime 显式注入的 TlonPaths 下。旧 JSONL 原样保留为离线档案，新系统不读、不导入、不双写、不自动删除。演武场的 JSONL 报告原料为数据库导出物，不是运行时存储或兼容层。

## 实施与验收

1. SQLite 权威存储与邮箱查询：原子多收件人提交、持久化幂等、读标记、退休状态、重启恢复。
2. 统一发信入口：人类 REST/SDK、agent 工具与 DSL、cron、退休交接、GitHub 入站、演武场；删除 EventBus 驱动的投递消费者。
3. Agent 工具必须返回真实投信结果，拒绝不能结束 session 或制造假成功；工具说明明确本地与网关承诺。
4. 验证队列溢出/通知故障不丢信、写盘失败回滚、并发重试、部分收件人无效、退休竞态、网关失败/未知不重发、已读独立。
5. 全量 scripts/check_all.sh，加隔离 TLON_HOME 的 dream + SDK 真冒烟；不触碰用户现有历史。

本决策覆盖 docs/design/mail.md 中旧的 JSONL 权威存储、异步投递与退信语义。实现完成后同步其现行说明及协议参考。

## 实现说明

主动 stop 为永久退休；idle drain 仍为休眠。注册表在启动与每 30 秒扫描本地未读邮箱以恢复遗漏的唤醒通知，运行中成员继续使用原有 rescan。关停会取消并等待生命周期任务，避免恢复扫描派出的启动在关停后继续装配。

本地入箱与网关信箱归属在数据库中明确区分，回执不会把网关算作本地成员。首启建表原子提交并在邮局接收请求前完成；只读查询不建表、不读取旧 JSONL。

## Review 后续修正

- 恢复循环每 30 秒检查，但空闲休眠后的旧未读只在该成员的 `mail_rescan_interval_seconds` 到期后才有资格触发恢复唤醒，避免搁置邮件反复启动认知循环。新的实时入箱通知不受此冷却影响；没有成功休眠过的邮箱仍立即恢复，失败的唤醒请求也不推进冷却。
- 不引入同内容时间窗去重。新的 request_id 表示新的投信意图，相同正文可以有意重复发送；稳定 request_id 才提供重试幂等。
- SQLite 初始建表在 runtime 的异步装配阶段经工作线程执行，PostOffice 构造不做 I/O；原子初始化和读就绪检查保留。
- 别名解析和投递目标验证收敛为一次，共用于 send/post；退休状态仍在提交事务中复检，已有请求重放优先于现时地址验证。

后续修正验证：新增 5 项回归覆盖休眠冷却、新信即时唤醒、不同请求的同文邮件、单次别名解析及无 I/O 构造；Python 单元 2022 项通过，隔离 dream + SDK 冒烟通过。

## 外围接线复核（2026-10-17）

收尾决定：SQLite 查询统一由 MailStore 承担，删除路径对象中的查询实现；异步业务经工作线程读取，不在事件循环连接数据库。邮局批量解析复用一次已知人快照，退休检查仍以提交事务为准。删除无生产者的 StageOutcome.mails 及无人调用的 AdapterManager.publish，不保留兼容入口；同步废止组件的文档描述。

- DSL 发信与工具投信分开处理失败：确定性 emit/forward 的邮局拒绝及基础设施异常记录结构化日志，不打断后续规则动作；认知 on-complete 原有逐 action 隔离保留。工具仍直接返回真实拒绝/未知结果，不制造退信。
- 已退休不等于运行资源已关停。stop 重试在持久退休标记存在但活成员仍在运行表时，必须继续关闭；只有关闭完成才移出运行表。取消或关闭异常不丢失该引用，也不清除永久退休标记。
- Telegram 对 submission_unknown 保存有界、按 user/chat 隔离的原始投信信封，提供 `/retry <request_id>`；复用全部内容和原键。缓存只在当前进程有效，重启或淘汰后明确拒绝重试，绝不重建信封或换键重发。
- 旧退信机制已废止，删除 tlon.mail.bounced 指标及 postmaster 发件人推断，cron 系统邮件只计正常发信。

外围修正验证：`scripts/check_all.sh` 14/14 全绿，Python 单元 2031 项、集成 16 项通过；最终补强的 DSL/on-complete 回归 4 项通过。实际 dream + SDK 验证入箱、同键重放和保持未读，临时 home、进程及端口均已清理。Telegram 使用真实 REST/SQLite 模拟提交成功后响应丢失，原键重试只产生一封邮件；未连接外部 Telegram 平台。

收尾验证：M2/M4/L2/L3 完成后，`scripts/check_all.sh` 14/14 全绿，Python 单元 2029 项、集成 16 项通过。移除 6 项废止入口测试，新增 4 项工作线程/实时查询回归；现存 cron、GitHub 测试也断言 SQLite 不在事件循环执行。隔离 dream + SDK 冒烟再次通过，临时目录、进程和端口已清理。

CI 后续发现 Adam 回信测试存在同步竞态：回信通知早于处理原信的标读写入，不能用前者推断后者完成。本地通过并未覆盖这一调度。测试改为主动阻塞标读、确认回信已到而原信仍未读，再放行并等待标读完成，保留全部行为断言，不更改运行时顺序或增加固定延时。
