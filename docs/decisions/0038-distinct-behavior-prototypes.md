# ADR 0038：以稳定行动习惯区分行为原型

状态：已接受（2026-10-18）。动态工作方式另记 ADR 0037，本轮采用现有原型实例化机制。

## 决策

近期补充或改造四类原型，让行为差异体现在可执行 spec 中，不绑定职业或人格：

| 方向 | 行为契约 |
|---|---|
| 计划后执行 | 改造长预算工具迭代：首次迭代生成最多 5 步计划，之后执行，交付前自评；计划和工具结果进入后续上下文。最多 30 轮、累计 1000000 stage token，不宣称已实现自动重规划。 |
| 短回合交流 | 改造精简上下文响应：最多 3 轮、累计 32000 stage token，保留人格、协议、当前任务、少量邮件及最近会话摘要；不额外做交卷前自评。 |
| 证据核验 | 新增 L2 原型：交付前按来源、计算或工具结果检查关键结论，区分事实、推断和未核实事项；明确通过评审才放行完成动作。仍是模型核验，不声称独立真实性证明或自动执行测试。 |
| 条件路由 | 新增无认知循环原型：仅处理投递给自己的事件，同时匹配指定发件人与正文正则才转发到指定地址；使用现有纯谓词、参数与 forward，不调用模型；不匹配不转发。 |

证据核验所需的评审标准通过 critique stage 的可选非空 `:instructions` 文本表达，保留系统 PASS/FAIL 输出协议；执行器不按原型 ID 或名称分支。未传入标准时仍使用通用自评提示；首行解析同时收紧为去空白后精确匹配 PASS/FAIL，拒绝仅有相同前缀的文本。核验无法解析或失败时不得当作通过；重新核验不能复用上一轮通过状态。

保留标准 L0/L1/L2、定址转发及上述四类，共 8 个内置原型。删除频繁反思迭代、低频反思迭代、超长预算迭代：前两者只有后台记忆审计频率不同，后者仅增加循环预算，缺少独特的行动方法。不调整 30 位初始成员的默认原型。改造沿用现有原型 ID；包内资源更新只影响新播种的目录，已有 ~/.tlon 原型库和成员文件不覆盖、不迁移，也不自动删除其中的旧原型。

## 验证

验证首次规划不逐轮重复、短回合预算与上下文、证据核验标准传入和失败/未知不放行、路由匹配与不匹配的真实动作。全部使用临时实例；质量门和冒烟不改当前 ~/.tlon 数据。
