# ADR 0042：删除成员与规则的确定性／认知性分类

> P5 状态：本文的 stage/recipe/旧规则机制已退役；历史决策保留，当前实现由 [ADR 0046](0046-programmable-workflows.md) 替代。

> P3c 当前实现：宿主能力统一定义为 Operation；Tool 与 DSL 共用定义和执行边界。旧工具名和类名仅记录当时设计，当前入口见 [工具手册](../reference/tools-reference.md)。
状态：已实施（2026-10-18）。用户批准本阶段实现并提交；报社端到端业务与可恢复效果求值留在后续阶段。

## 决策

1. 成员没有执行类别，规则统一为 on、when、actions 和 fuel。删除顶层规则 loop 字段、唯一会话规则、仅邮件可触发会话以及按类别禁止 forward 的限制，不做旧格式兼容。
2. 现有上下文、stages、until 和预算组成独立 SessionRecipe。普通 DSL 动作 `(run-loop (quote {...}))` 产生会话执行请求，可以位于条件、函数和传统循环内。标准 quote 将配方中的阶段表达式作为数据传递，不提前求值。是否出现该动作不产生新的成员类别。
3. 所有规则统一按成员串行执行效果。run-loop 按本次请求装配上下文与驱动器，完成后继续后续动作；同一成员可在不同规则、不同事件上调用不同配方。LLM／工具等待仍属于公开 active，四态门控覆盖所有规则、扫描、反思和效果。
4. 保留真实触发事件／邮件引用，执行会话后仍能转发该邮件。邮件读状态与规则类别无关；已排队和执行中的工作不得由扫描重复启动。会话恢复必须采用已记录的配方和执行来源，不能任取成员的第一条规则。
5. tlosure 继续求值产生效果请求，宿主执行实际 I/O；本阶段不声称效果结果已经可以绑定为任意表达式值。报社需要的结构化业务状态、编辑结果继续分支、期刊冻结和投递恢复在后续完整效果求值阶段实现。
6. 文档、代码符号、注释、原型、提示与测试删除上述分类和相应断言；纯函数、确定的计算／报告等客观机制术语不属于成员类型分类。历史决策标注被本 ADR 废止，保留可审计的历史说明。

## 验证

普通循环无模型调用；条件分支产生会话请求；同成员多规则／非邮件事件的会话串行执行；会话后转发真实触发邮件；效果顺序、共享预算、四态门控、重扫去重、按原配方恢复。使用隔离 TLON_HOME 跑完整质量门与真实冒烟，不修改现有 ~/.tlon 数据。

验证结果：最终 `scripts/check_all.sh` 14/14 全绿，单测 2305 通过、15 跳过，集成测试 26 通过；真实隔离 dream + SDK + 本地模型冒烟验证非邮件事件运行会话、普通 while 实际发两封邮件、条件会话结束后转发原始邮件，模型仅调用两次且 finishTurn 不标读。临时实例与端口已清理。

复核补齐：普通循环和零捕获能力闭包使用统一的宿主效果收集上下文，不能因 while 返回 nil 而丢动作，也不能因引用返回值而重复执行；重复中断恢复继续保留剩余效果。删除分类门控后，归档逻辑显式跳过管理员已删除的成员，避免重新建立其目录。代码、内置原型和文档使用新语法；当前 ~/.tlon 未改动，旧顶层 loop 配置需由后续明确授权同步。
