# ADR 0028：持久邮箱与单 session 执行

状态：2026-10-11 接受；执行与触发机制由 [ADR 0042](0042-unified-member-rule-execution.md) 修订。当前实现见 [runtime](../design/runtime.md) 与 [mail](../design/mail.md)。

## 保留的决定与理由

邮件必须在通知之前持久入箱，通知丢失可以通过启动与周期扫描补偿。运行中的成员可以主动查邮箱；模型上下文不由后台投递回调擅自插入新消息。公开活跃状态覆盖正在执行的模型和工具工作。

同一成员串行推进程序，一次最多一个会话；会话用独立 uuid 标识。会话 journal 是恢复事实源，责任集 id 持久记录，用来选择人类失败通知的锚点。终止通知只发给责任集内已知人类发件人，避免成员之间故障通知互相放大。

读状态由成员显式管理。`checkInbox` 返回邮箱内容，`markRead` 选择具体邮件；完成处理、结束会话、进入等待不代替标读。成员可以保留未读，不设置强迫清空邮箱的完成门。

## ADR 0042 替代的执行决定

过去把 mailbox 作为唯一调度队列、依未读快照决定创建固定会话的实现已退役。所有规则现在统一是 on/when/actions；事件先进入成员串行工作者，程序按需请求独立会话配方。非邮件事件也可运行会话，来源邮件引用保留，不再有固定规则分类或专属完成环境。

为避免重复通知和扫描重复执行，系统对邮件及规则身份维护待处理去重与分派完成记录；保留未读不意味着持续重复启动已完成规则。会话恢复采用 journal 记录的配方、来源和剩余效果，不从成员规则中任取一条配置。

这些修订替代了旧的唯一会话规则、仅邮件触发、触发邮件退役以及基于规则类别自动标读的限制。通用业务状态、任意模型结果继续分支和完整效果事务恢复仍是后续能力，不能由此推导已经具备。
