# ADR 0043：以报社验证可返回结果的成员程序

状态：已实施（2026-10-18）。承接 ADR 0042，用户批准继续报社端到端阶段。

## 决策

报社是普通成员；订阅、退订、收稿、编辑、期刊冻结和分发是 DSL 业务程序，不新增 Python 报社类，也不引入成员执行类别。

1. tlosure 使用一个可暂停的 generator 求值内核。同步驱动保持纯数据求值；异步驱动在效果 builtin 调用处交给宿主执行，把实际结果送回 let、if、函数及循环。燃料与深度在同一内核计量，未选分支不调用模型。
2. runtime 提供通用 state-get、state-put、llm-call、send-mail。成员私有 program.sqlite3 保存结构化状态和每次规则执行的原始程序、触发输入及逐步效果结果。状态写入和该效果结果同事务提交。程序按原始输入重放，已完成效果直接返回记录；效果名和参数变化时报错，不猜测恢复。
3. 沿用成员串行 worker、四态与管理员收尾门控；I/O 等待保持 active。未完成程序先恢复，不能因源邮件已读而丢失；死亡不执行，睡眠等唤醒。模型调用不附工具，保留人格、RULES 与协议，输出上限传到 provider，规则共享有限调用预算。
4. 邮件效果返回邮局真实回执。稳定请求 ID 复用邮局已有的原子幂等提交，覆盖入箱后记录前崩溃。拒收明确返回拒收；无法确认的异常不标记成功。网关只承诺现有的尽力投递，不声称外部恰好一次。
5. 模型成功输出落盘后可复用；上游已生成而本地未记录时可能再次调用，不承诺模型恰好一次。期刊在任何投递之前冻结正文、真实稿件来源 ID、期号和订阅人快照。逐人投递用期号和地址作稳定请求 ID；重试冻结期刊不重新编辑，不重发已成功投递的报纸。
6. 示例用邮件主题表达 subscribe、unsubscribe、submit、publish:<期号>；初版按明确出版命令运行，定时触发可复用现有 cron 邮件，不扩张 cron 引擎。来源由 runtime 提供的真实触发邮件生成，来源附录由 DSL 拼接，不采信模型生成的来源编号。示例随包发布，首装不自动增加报社，不改当前 ~/.tlon。

## 验收

订阅 A/B/C 后 C 退订；重复输入同一稿件不重复收录；普通条件只在出版有稿时调用模型；空白编辑结果不得分发，来源附录仅含真实投稿邮件 ID；冻结后出现的新稿/订阅只影响下一期。模拟 A 已入箱但程序日志未记录即中断，重启后回收相同回执；B 短暂失败后重试，A/B 各一份、C 无报纸，冻结内容不变。补语言、状态事务、恢复和四态回归，跑完整质量门及隔离 dream + SDK 真实冒烟。

恢复补充：一个事件匹配的全部规则先在同一事务登记，按序执行；前序未完成时阻止后续状态写入。纯表达式／参数／重放冲突记为失败终态，保留已提交效果，不冒充成功，也不永久堵塞队列；未知 I/O 保持待恢复。装配就绪与业务恢复分离，恢复及 boot 由 worker 执行，避免业务模型调用受启动超时反复中断。

## 验证结果

最终 `scripts/check_all.sh` 14/14 全绿：2375 项单元测试通过、15 项跳过，34 项集成测试通过。回归覆盖表达式／闭包／普通循环的效果结果、重放预算、状态与效果原子提交、同事件多规则恢复、已读源信恢复、boot 临时 I/O 重试、慢恢复不阻塞启动和失败终态。

隔离 TLON_HOME 的真实 dream + SDK + 邮局数据库冒烟通过：两篇真实投稿进入同一期，A/B 各收一份，模型调用一次，相同期号重复出版没有增发。临时数据、进程和端口已清理，当前 ~/.tlon 未修改。wheel 检查确认五个报社示例文件随包安装。

冒烟发现现有 SDK 与服务端存在协议差异：请求需 X-Tlon-WebUI 头，并省略旧 username 字段。仅在冒烟脚本适配，SDK 本体未在本阶段修改；不把这次冒烟当作未修改客户端的兼容性证明。
