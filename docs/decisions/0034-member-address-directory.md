# ADR 0034：统一成员寻址黄页与信息边界

> P3c 当前实现：宿主能力统一定义为 Operation；Tool 与 DSL 共用定义和执行边界。旧工具名和类名仅记录当时设计，当前入口见 [工具手册](../reference/tools-reference.md)。
- 状态：已采纳（2026-10-17）
- 修订：ADR 0024 的黄页范围与协议表达；保留主观社会身份、私有联系簿与人格边界。

## 决策

成员寻址黄页覆盖当前本地投递层可识别、未退休的普通成员、守护者 Adam 和 SQLite 已登记的通信成员。离线、休眠不影响入选；人类地址不依赖在线会话，历史 guest 若仍登记且可投递同样列出。外部网关、外部邮件来源、postmaster 系统发件地址、已退休地址和无法解析的历史地址不作为成员列出。以真实投递解析的地址归属为准，按地址去重并稳定排序；不增加账户认证或社会身份认证。

工具改名为 `listMembers`，删除旧 `listAgents` 工具及注册，不保留别名或 fallback。每项仅 `id`、`name`、`address`：id 是地址 local-part（例如 rika，而非内部存储 id human:rika），name 是已有显示名（无独立显示名的地址使用 local-part），address 为完整邮件地址。输出不携带人类／agent 类型、职务、组织、可信等级、运行状态或血缘。生命周期操作仍由原有生命周期接口检查真实目标与权限；黄页不授予启停等权限。

`listMembers` 与 DSL `member-roster` 使用同一份投递层目录，不从 agent 状态列表、在线会话或私人联系簿另建副本。新成员与退休状态在下次查询时反映；不要修改 agent 注册表的全量枚举来加入人类／Adam，以免改变启停、spawn 等机制。

## 公共协议

黄页是系统公开的寻址信息，所有成员可查询、引用和转告其名字／地址，并标明「当前黄页列出」与范围。它不认证任何职务、组织、能力或可信程度；「没有权威社会身份表」不表示「没有可查询通讯录」，更不构成黄页保密规定。尚不了解对方不影响其查询公开寻址信息。

黄页的公开性不扩展到私人联系簿、人格文件、邮件正文或记忆。这些材料继续遵守既有私有访问边界；不得为了列举通信对象而读取、转交他人的私有材料。公开黄页与社会身份判断保持分离，不强制成员信任某人、承认职务或执行请求。

## 实施与验证

投递解析层生成唯一黄页，由邮局提供查询，经注册表注入工具与 DSL 查询。查询不调用 LLM、不唤醒成员、不创建邮箱；使用现有 SQLite/解析器，无新依赖。统一协议和 Adam 欢迎信使用新工具名。

回归覆盖：普通成员／Adam／已登记离线通信成员可发现；未登记、退休、删除配置后的残留地址、系统发件地址及外部地址不出现；地址冲突按实际路由归属只列一项；只输出三个公开字段、不暴露 human: 前缀；工具与 DSL 结果同源；新登记／退休／重启及时生效。全量质量门 scripts/check_all.sh，隔离 dream + HTTP 邮件与目录冒烟，不修改已有成员记忆或联系簿。
