# ADR 0031：WebUI 邮箱同步、线程展示与人类已读管理

状态：已接受（2026-10-17）

## 决策

- SQLite 是邮箱和每个收件人已读状态的权威；打开页面、查看线程或重连均不标读。观察他人邮箱保持只读。
- SSE 流实际打开后才报告 connected。页面先订阅通知，再拉快照；每次重新连通补拉快照。快照与加载期间的实时邮件按 id 合并，重复邮件可更新 read；切换邮箱后旧请求不得影响新邮箱。发信和标读的返回结果也不得被较早发起的快照覆盖。
- 邮箱 GET 增加 before（上一页最早 mail id）游标，按数据库 timestamp/rowid 稳定分页；响应添加 has_more 和 next_before。分页包含本人 inbox + sent，观察接口不暴露他人 read。UI 提供“加载更早邮件”和历史未全部加载提示，重连补拉必须覆盖已知最新邮件之间的缺口，不能只拿固定 100 封。
- POST /inbox/read 接收 username、read（布尔值）以及 mail_id 或 thread_id（二者恰好一个）。只更新该人类成员的收件关系；线程操作在一个事务中覆盖该线程全部已收邮件，包括当前未加载的历史。返回 mail_ids 与 read；未找到可操作的收件关系返回 404。不会修改收件人 agent 的已读状态。
- 线程仍严格按 thread_id 分组，不按主题或参与者猜测合并。优先显示根邮件的稳定主题（无主题取正文摘要），再显示参与者、日期、短线程 id 和未读数；根邮件未加载时明确提示。缺失的回复父邮件保留引用提示，不静默隐藏；筛选覆盖全部已加载正文。

## 实现约束与验证

复用现有 React、EventSource、SQLite 和测试依赖；不引入新状态管理库或历史兼容层。REST/SDK 原邮箱读取行为保留，新增分页元数据不改变默认读取上限。查询与写入在工作线程执行。

回归覆盖订阅就绪、重连超过一页、快照/实时/读状态修改交错、过期请求、同时间戳分页、仅操作本人收件关系、线程批量标读持久化及未加载历史。完整质量门与隔离 dream/SDK/浏览器冒烟完成后记录验证结果。

## 验证记录（2026-10-17）

- 最终 `scripts/check_all.sh` 14/14 全绿：Python 单元 2043、集成 16、WebUI 77、Operator 24 项通过；TS 检查、生产构建与打包通过。
- 控制器测试覆盖延迟 SSE 不能覆盖未加载邮件的整线程标读结果，以及断线期间本地发送不能截断补信边界。
- 隔离 dream + SDK：投信与同键重放通过；真实浏览器验证 130 封线程在仅加载 99 封时整线程标读，加载历史后 130 封全部已读。单封改未读后刷新仍保留；观察他人没有写操作。
- 停止测试服务后另提交 125 封信，浏览器自动重连后全部补齐，保持原线程选择。独立 SQLite 校验最终共 258 封，长线程为 129 已读、1 未读。
- 冒烟过程说明：断线注入进程未启动其独立 EventBus，产生通知失败日志；125 封的事务提交成功，恢复验证依靠持久快照。清理脚本首次检查端口早于重启实例退出，出现一次时序断言失败；等待退出后独立确认测试端口已释放、临时 home 已删除。未触碰用户现有邮箱。
