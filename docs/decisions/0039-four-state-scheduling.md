# ADR 0039：成员四态调度与邮件工具解耦

状态：已接受，已实现（2026-10-18）。用户确认全部三项接口与权限选择。详细契约见 [agent-scheduling-states](../design/agent-scheduling-states.md)。

后续修订：[ADR 0041](0041-admin-scheduling-controls.md) 允许管理员提前唤醒，并增加等待、定时睡眠管理操作；普通邮件仍不能提前唤醒。

## 决策

1. 对外统一 active（有成员工作，包括等待 LLM/工具结果）、waiting（无工作，来信可激活）、sleeping（睡至指定时刻，来信只入箱）、dead（永久终态）。实例驻留与装卸、启动与故障属于诊断，不是额外成员状态。
2. 死亡拒收新信，保留人格、记忆、邮件与 journal；死亡后不再生成成员告别信，原退休礼改为只读归档清点事件；复用现有退休标记的事务拒信，不新增第二份死亡事实源。新增睡眠期限存储使用同一实例 SQLite 文件，独立生命周期接口管理，不做旧 API 兼容或数据迁移。
3. sendEmail 删除 is_complete，仅投信；删除 silence 与面向任意成员的 stopAgent 工具。所有认知成员获得只绑定自身的 finishTurn、sleepUntil、exitAgent、getSelfState。三个结束工具必须单独一轮；发信、标读与结束分开调用，接受额外轮次成本。
4. sleepUntil 只接受未来的带时区绝对时间，归一 UTC。完成当前会话、收齐工具与后台反思后提交睡眠/退出；状态意图通过 StageOutcome 和 journal 表达，调度器在安全点兑现。睡眠期限持久化，重启不重新计时；到期检查持久邮箱，无工作不调用模型。~~不提供提前唤醒。~~ 管理员可提前唤醒，见 ADR 0041。
5. 普通成员不管理其他成员状态。管理端终止采用排空后死亡；有活动工作则登记意图，完成后执行，不强制取消。等待实例可回收，回收不意味着睡眠；死亡、睡眠约束所有启动、重扫、投递和反思入口。
6. DSL 区分结束工作与发送邮件，原型的交付评审在实际邮件工具派发前执行，不能在 finishTurn 时补审已发邮件。同步运行提示、原型、工具描述、API、SSE、WebUI 和测试，不留旧参数别名。
7. 不修改当前 ~/.tlon，不执行 git 提交、推送或 PR 操作；这些分别等待用户明确指示。

## 实施阶段

1. 生命周期持久化与四态调度、安全转换和恢复。
2. 独立状态工具、邮件解耦、DSL/原型/提示同步。
3. Facade、服务端与 WebUI 统一状态，集成与真实隔离冒烟。

各阶段允许并行修改无冲突模块，最终由主会话复核，scripts/check_all.sh 全绿且真实冒烟通过后才报告完成。
