# ADR 0044：统一能力定义，分离 DSL 与 LLM 调用入口

日期：2026-10-19。

状态：完整方案已接受；用户已授权提交设计 PR 并开工 EPIC A，P1 最小契约已实现并通过本地验收，待 PR 合并，生产业务尚未切换，合并仍由人类确认。

## 背景

Capability artifact 与 Python Tool 分别绑定了实现形态和调用入口。前者不能引用其他 Capability，也不进入 LLM 工具面；后者将 schema、宿主实现和协议定义耦合。条件语境维护不同注册表；邮件等动作由程序和会话路径分别解释。概念可分类，但组合规则不统一。

## 决策

1. 统一 Operation：一份输入/输出契约、一份实现；实现为宿主原语或 tlosure 组合。Tool 是面向 LLM 的投影，DSL 是另一入口。
2. 复合操作可静态具名依赖其他复合操作，加载时检查缺失、环和传递效果；纯语境按效果准入，而非另维护能力白名单。
3. 共用宿主执行权限、预算、调用身份、效果提交及结果语义；不合并程序/会话生命周期，不废除现有邮局、程序存储、journal 和调度机制。
4. 确定性纯计算与外部 read/write 分开；复合效果从依赖推导。权限始终属于原调用成员，不属于 artifact 作者。
5. 成员执行授权与工具视图分离。Behavior 选择更窄的请求级视图，执行时再检查当前权限和状态。复合封装不能绕过叶子检查。
6. 保留 Prototype 的行为打包/复制实例化、人格/模型分离、staging/人工审批。Capability 不保留独立执行体系，MemberCapabilities 装配对象改名 MemberServices。
7. 使用已有依赖中的成熟 schema 校验；不新增流程语言、通用审批系统、外部工作流引擎、版本协商或兼容层。

## 替代范围

- 目标上修订 ADR 0020/0021 所涉及的宿主注册接口与调用准入，不废止 tlosure 语言语义。
- 扩展 ADR 0043 的效果返回、程序快照/重放到共享调用契约；保留其已完成验收记录。
- 将 capabilities design 中“只进 DSL、不能引用能力”的 v1 边界替换为可组合操作和两种入口；在实施前仍准确标记为当前限制。
- 保留 ADR 0019 包依赖方向、0030 邮局事务、0039/0041 四态调度、0035 原型实例化原则。

上述是目标替代关系，不表示旧机制已删除。当前运行机制仍以已有 design/reference 为准；相关阶段完成时同步改写当前文档。

## 备选与理由

- 仅给 Capability 加 Tool 包装：能暴露给模型，但无法解决参数/效果/恢复/授权重复，拒绝作为最终架构。
- 把全部操作改成 Python Tool：失去成员通过受限语言组合与提案的能力，不采用。
- 全面换工作流引擎或重写 DSL：成本和影响超出目标，已有持久化机制可复用，不采用。

## 代价与实施

需要统一宿主输出 schema、增加依赖/定义快照与请求视图、处理旧 schema 的明确拒绝。不会自动迁移用户数据，也不会静默删除旧运行。
