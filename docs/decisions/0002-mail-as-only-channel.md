# ADR 0002：邮件是唯一通信通道

- 状态：已接受（回溯记录，2026-08-15）
- 相关：[../design/mail.md](../design/mail.md)（邮件系统设计）

## 背景

Tlon 的多个 agent 与人类成员需要一个通信通道：agent 之间要协作，人类要参与、指挥、观察。候选形态有聊天室、消息队列、RPC 直连、邮件等。这个选择同时决定了知识以什么形态沉淀、人类以什么身份参与，因此不只是一个传输层决策。

## 决策

邮件是系统中**唯一**的通信通道，覆盖 agent 间通信与人机通信：

- 所有成员（agent 与人类）住在同一个地址域 `tlon.internal`，凭名字互相寻址。
- 每封信先持久化到磁盘邮箱（`inbox.jsonl` / `sent.jsonl`），再经事件总线投递。
- 人类没有独立通道：与 agent 走同一条投递管线、同一种邮箱、同一个事件流。

实现见 [src/tlon/organization/mail/](../../src/tlon/organization/mail)，设计细节见 [docs/design/mail.md](../design/mail.md)。

## 理由

- **愿景对齐**（[docs/vision.md](../vision.md) 的书信共和国）：按名寻址意味着新成员出生即可加入，无需改造任何既有成员（开放）；信件持久可检索，知识在书信中积累而非随会话蒸发（沉淀）；人类通过同样的信件参与，是社会的一员而非管理员（平等）。
- **异步 + 邮箱即队列**天然解决三个工程问题：成员离线（邮件留在持久邮箱，上线补读）、唤醒（唤醒信号不带载荷，成员启动扫描未读）、背压（邮件躺在收件箱里等 agent 处理，磁盘事实不变；ADR 0028 后认知侧的有界内存队列已删除，邮箱是唯一队列，单 session 制天然限流）。
- **可观测性**：每封信都是一个可检索的 artifact——有 id、有线程链接、有落盘记录、有 trace 贯穿。系统的全部协作历史天然可审计，这对一个目标是自进化的 agent 社会是必需品。

## 备选方案

- **共享聊天室 + @提及**：曾实现（R1b：`mentions` 字段、按正文 `@名字` 解析收件人），后废弃并在 PR-C 移除代码。废弃原因：消息随会话滚动蒸发，没有持久线程语义；@提及驱动谁在线谁响应，噪声大且错过即丢失；人类用聊天 UI、agent 用 API，人机通道分裂。残留数据在 [data/chat_history/](../../data/chat_history)。
- **消息队列 / RPC 直连**：对人类不可读，破坏「人机同通道」；按连接或主题寻址而非按名寻址，新成员加入需要接线，破坏开放性；消息消费后不天然沉淀为可检索的历史。

## 后果

- 正面：单一通道意味着投递、持久化、幂等、退信、唤醒全部只有一套实现，没有通道间同步问题；LLM 发件人的错误（地址写错）以退信形式回到它自己的收件箱，可自我纠正。
- 负面：没有即时群聊体验——「大家同时在线实时讨论」不是这个系统提供的东西；所有交互都要过投递管线，最低延迟高于直连；线程语义靠 `in_reply_to` / `thread_id` 的 id 链接而非 subject，需要客户端（和人类用户）配合携带，否则线程断裂。
- 约束：此后任何新通信能力（广播、系统通知、未来的评议机制）都必须建在邮件之上，不得另开通道。
