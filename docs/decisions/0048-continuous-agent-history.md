# ADR 0048：跨事件持续维护一段 Agent 主历史

状态：已接受，尚未实施。2026-10-24。

## 决定

同一 Agent 的所有收件进入同一段持久主历史，不按发件人、邮件线程或事件另建会话。新邮件、模型响应、完整工具结果和核验意见追加到末尾；优先保留已有提示前缀，不再每封邮件用近期邮箱、recap 和动态资料重新组装上下文。主历史是普通 module 管理的私有程序状态，不是新的 Session 引擎。

历史生命周期跨事件、休眠与重启；每次事件仍有独立 run_id、fuel、预算根和完成状态。模型、工具、核验和压缩消耗当前事件的同一个预算根。历史存在不计为在途执行，不阻止排空或休眠。

历史保存采用完整交互组的增量检查点，不等待整个事件成功才保存。外部效果以 ProgramStore 回执为权威；历史是模型的工作视图，不能成为第二份执行账本。失败后保留已知进展，结果未知时阻止主历史继续推进，不以新事件或新预算绕过未知效果。

提示输入采用显式生效策略：初始化时固定主历史的系统提示、工具定义及模型配置；后续事件复用，不自动追随人格或配置文件的变化。配置变更显式应用于事件之间，默认保留消息历史，记录变更并允许此次必要的缓存失效。实时权限撤销、模型协议和上下文窗口约束仍必须遵守，不能为缓存继续使用撤销权限或发送非法消息。不支持自动清空重开、旧新双源或失败 fallback。

具体保存点、失败矩阵、压缩和配置分类见[持续主历史设计](../design/continuous-agent-history.md)。阶段范围、验收和删除项见[实施计划](../design/continuous-agent-history-plan.md)。

## 理由与代价

邮件是输入事件，不必是认知上下文的结束。保持实际模型与工具历史可以保留工作连续性，并避免滑动邮箱窗口和动态资料重写长前缀。普通数据加现有状态操作符合 ADR 0046，不需要长驻求值器、旧 AgentSession、stage 或新的会话调度器。

一段主历史会混合不同任务和发件人的资料；模型可见不等于允许转发。长期历史增加输入体积，压缩会丢失细节并改变前缀；持久检查点也有存储成本。缓存命中不能保证，验收必须同时检查任务正确性、输入量与真实计费反馈。配置不会自动生效是刻意的产品取舍，必须可检查待生效差异和当前有效版本。

## 未选择的方案

- 每封邮件重建：执行简单，但丢失完整工具进展，反复改变前缀。
- 按邮件线程拆分：隔离更强，但不符合所有邮件共用 Agent 主历史的选择。
- 一个永不结束的执行根：把历史与预算、排空和恢复绑定，最终耗尽额度，不能解决持续工作。
- 新 Session 引擎或状态图：重复 ProgramDriver、ProgramStore 和普通 module 的职责。
- 永久冻结全部配置：虽然前缀稳定，却无法正常撤权、调整模型或升级工作程序。

## 修订关系

延续 ADR 0046 的普通程序与单一恢复权威、ADR 0047 的按需文件读取。替代标准 agent/respond 按事件重建上下文的策略；不恢复 ADR 0025 的旧冻结/滑动邮箱拼装或 ADR 0028 的旧 Session 执行机制。ADR 0015 的缓存目标保留；预算仍以当前事件执行根为边界，不回到旧 Session 预算模型。
