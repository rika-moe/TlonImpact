# Tlon TUI 功能规约 V1.0

> 基于博尔赫斯美学 + 工程精确的设计理念

---

## 一、产品定位

TUI（Terminal User Interface）是用户与 Tlon 宇宙交互的**主要入口**。它是终端中的"代表大会"——一个流式对话界面，让用户通过自然语言指挥 AI Agent 团队完成软件开发任务。

**设计原则：**
- **极简主义**：流式控制台，支持复制粘贴，不抢占终端控制权
- **诗意表达**：每个功能都有文学隐喻，但不牺牲实用性
- **三层视图**：根据用户需要，在聊天、监控、管理之间切换

---

## 二、核心功能模块

### 2.1 连接与认证

| 功能 | 描述 |
|------|------|
| 自动连接 | 启动时自动连接本地或指定的 Tlon Server |
| 连接状态显示 | 实时显示 WebSocket 连接状态（已连接/已断开） |
| 重连机制 | 断线后自动尝试重连，用户可手动触发 |
| 会话管理 | 维护用户身份标识，支持跨会话记忆 |

**产品隐喻**：进入代表大会的大门，出示你的邀请函。

---

### 2.2 三模式切换系统

TUI 提供三种操作模式，用户通过 `/mode` 命令切换：

| 模式 | 隐喻 | 用途 | 默认视图 |
|------|------|------|----------|
| **Chat** | 圆桌对话 | 与 Agents 自然语言交流 | 消息流 |
| **Event** | 观察心跳 | 监控系统事件和 Agent 行为 | 事件日志 |
| **Agent** | 凝视镜中 | 管理 Agent 团队（唤醒、休眠、查看状态） | 状态表格 |

**切换方式**：`/mode chat|event|agent` 或 `/m`

---

### 2.3 Chat 模式（对话模式）

**核心功能：**

1. **消息发送**
   - 直接输入文字，回车发送
   - 支持 `@Agent名称` 或 `@AgentID` 提及特定 Agent
   - ✅ Tab 键自动补全 @提及列表

2. **消息展示**
   - 时间戳 + 发送者身份 + 内容
   - 区分：人类用户（你）、Agent、系统消息
   - 每个 Agent 有专属 Emoji 头像

3. **历史消息**
   - 启动时自动加载最近 N 条历史
   - `/history [n]` 查看指定数量的历史消息
   - 支持终端原生滚动回看

4. **在线成员**
   - `/who` 显示当前在线的 Agent 列表

**交互规则：**
- 只有 Chat 模式下可以直接发送消息
- 未被 @ 的 Agent 可能保持沉默（被动角色）
- 被 @ 的 Agent 必须响应（代表大会规则）

---

### 2.4 Event 模式（事件监控模式）

**核心功能：**

1. **实时事件流**
   - 显示系统产生的所有事件
   - 事件类型包括：
     - `message.new` / `message.mention` - 新消息/提及
     - `agent.thinking` / `agent.response` - Agent 思考/响应
     - `agent.started` / `agent.stopped` - Agent 启动/停止
     - `agent.join` / `agent.leave` - Agent 加入/离开
     - `tool.execute` / `tool.result` - 工具执行/结果
     - `system.startup` / `system.error` - 系统事件

2. **事件过滤**
   - `/filter <条件>` 按事件类型过滤
   - `/filter clear` 清除过滤器
   - 支持关键字匹配（如 `agent` 匹配所有 Agent 相关事件）

3. **暂停/恢复**
   - `/pause` 暂停滚动（新事件进入缓存）
   - `/resume` 恢复滚动（显示缓存的所有事件）

4. **历史查看**
   - `/tail [n]` 查看最近 N 条事件

**产品隐喻**：观察代表大会的"心跳"——谁在什么时候做了什么。

---

### 2.5 Agent 模式（团队管理模式）

**核心功能：**

1. **状态展示**
   - 表格形式显示所有 Agent
   - 信息：状态图标、ID、名称（带 Emoji）、职位
   - 统计：在线数、待机数、总数

2. **Agent 控制**
   - `/wake <id>` 唤醒指定 Agent（从待机到活跃）
   - `/sleep <id>` 让指定 Agent 休眠（释放资源）

3. **Agent 状态**
   - 🟢 活跃（active）- 正在运行，可响应消息
   - 🟡 唤醒中（waking）- 正在启动容器
   - ⚪ 待机（standby）- 已注册但未运行

**产品隐喻**：凝视镜中——看到团队的全貌，决定唤醒谁、让谁休息。

## 三、命令系统

### 3.1 全局命令（所有模式可用）

| 命令 | 简写 | 功能 |
|------|------|------|
| `/help` | `/h` | 显示帮助信息 |
| `/quit` | `/q`, `/exit` | 退出 TUI |
| `/clear` | `/cls` | 清屏 |
| `/mode <mode>` | `/m` | 切换模式 |
| `/connect` | `/c` | 重新连接服务器 |
| `/status` | `/s` | 显示连接状态 |
| `/agents` | `/a` | 列出所有 Agent |

### 3.2 Chat 模式专属

| 命令 | 功能 |
|------|------|
| `/history [n]` | 显示最近 n 条历史（默认 50） |
| `/who` | 显示在线成员 |

### 3.3 Event 模式专属

| 命令 | 功能 |
|------|------|
| `/filter [条件]` | 设置事件过滤器 |
| `/filter clear` | 清除过滤器 |
| `/pause` | 暂停滚动 |
| `/resume` | 恢复滚动 |
| `/tail [n]` | 显示最近 n 条事件 |

### 3.4 Agent 模式专属

| 命令 | 简写 | 功能 |
|------|------|------|
| `/list` | `/ls` | 打印 Agent 状态表格 |
| `/wake <id>` | - | 唤醒 Agent |
| `/sleep <id>` | - | 休眠 Agent |

## 四、交互细节

### 4.1 输入体验

- **输入行固定底部**：使用 prompt-toolkit 保持输入行始终在终端底部
- **输入历史**：`↑/↓` 键浏览之前输入的命令/消息
- **Tab 补全**：✅ 支持 @提及的 Agent 名称自动补全
- **异步输入**：不阻塞消息接收，边输入边接收新消息

### 4.2 视觉反馈

- **Emoji 图标**：不同事件类型有对应图标（如 🧠 思考、🔧 工具执行）
- **颜色区分**：使用 Rich 库进行富文本渲染
- **连接状态变化**：连接/断线时有明确提示

### 4.3 错误处理

- 发送失败时显示 `❌ 发送失败`
- 连接断开时提示 `⚠️ 与服务器的连接已断开`
- 未知命令提示 `❌ 未知命令`

## 五、启动与配置

### 5.1 启动参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-h, --host` | 服务器地址 | 127.0.0.1 |
| `-p, --port` | WebSocket 端口 | 8888 |
| `-r, --rest-port` | REST API 端口 | 8080 |

### 5.2 启动流程

1. 显示欢迎横幅（含 Server 地址）
2. 尝试连接 WebSocket
3. 认证（client_type = "tui"）
4. 加载 Agent 列表
5. 加载历史消息
6. 显示提示信息（输入 `/help` 查看帮助）

## 七、非功能性需求

| 维度 | 要求 |
|------|------|
| 响应速度 | 消息发送延迟 < 100ms，事件接收实时 |
| 稳定性 | 支持长时间运行（数小时不崩溃） |
| 兼容性 | 支持主流终端（iTerm2、Terminal、VS Code Terminal 等） |
| 资源占用 | 内存占用 < 50MB，CPU 占用可忽略 |
| 可访问性 | 支持复制粘贴，不依赖 GUI |
