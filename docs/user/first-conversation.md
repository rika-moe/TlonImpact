# 第二章：你的第一封信

> 在特隆，没有聊天室。有的是邮路——每封信都有明确的收件人，每个收件人都有一只邮箱。

---

## 开始之前

先让梦境运转起来。开两个终端：

```bash
# 终端 1：启动服务端
uv run tlon dream

# 终端 2：打开 Operator 控制台，以你的名字登录
uv run tlon ops --username alice
```

`--username` 决定了你的邮件身份。缺省是 `guest`；这里用 `alice`，你的地址就是 `alice@tlon.internal`。

控制台打开后默认停在 **mail 视图**：左栏是线程列表，右栏是选中线程的会话流。底部有一行提示：`1-5 / tab / ←→ switch view · q quit`。

现在，你的邮箱是空的。让我们改变这件事。

---

## 写第一封信

按 `c`，进入写信表单。四个字段，回车逐字段前进：

```
New mail                    enter 下一字段 / 提交 · esc 取消
╭──────────────────────────────────────────────╮
│ To      : gu-yanxi@tlon.internal             │
│ Cc      :                                    │
│ Subject : 你好                               │
│ Content : 我刚装好 Tlon，想确认团队是否在线。 │
╰──────────────────────────────────────────────╯
```

- **To** 填 `gu-yanxi@tlon.internal`——顾言蹊，客服，团队的第一接触点。也可以直接写她的名字 `顾言蹊` 或 id `gu-yanxi`，服务端都会解析成同一个地址。
- 在 Content 字段按回车，信就发出去了。任何字段下按 `esc` 可以取消。

你的信会立刻出现在右栏会话流里（本地追加），然后被投递进顾言蹊的邮箱。

> **为什么必须写收件人？** Tlon 的邮路没有"广播给空气"这回事。一封信没有具体收件人，就没有人理你——agent 看不到"别人的信"，它们只读自己的邮箱。这是邮件模型的基本法。

## 等回信

如果你的团队刚启动，顾言蹊可能正在睡觉。没关系：**信会在她的邮箱里等她**。沉睡的 agent 收到邮件时会被唤醒——这需要几秒钟——醒来后她扫描未读邮件，逐封处理。

几秒到几十秒后，回信落进你的邮箱，控制台实时刷新：

```
gu-yanxi → alice · 14:23:07
Subject: Re: 你好
收到，顾言蹊在线，随时为您服务~ 团队其他成员也已就绪：
开发林知遥、运维江予白、项目经理沈清晏、产品苏晚晴、
数据分析谢云舒。需要我帮你转接哪一位吗？
```

左栏里，你们的往来被聚合成**一个线程**——同一个主题的往复不会散成一滩流水账。

## 回复：线程自然生长

左栏用 `↑↓` 选中这个线程，按 `r` 回复。表单自动填好收件人（顾言蹊的地址）、`Re:` 前缀的主题，并继承线程头——你只需要写正文：

```
Reply                       enter 下一字段 / 提交 · esc 取消
╭──────────────────────────────────────────────╮
│ To      : gu-yanxi@tlon.internal             │
│ Cc      :                                    │
│ Subject : Re: 你好                           │
│ Content : 帮我看看一个个人博客项目该怎么起步。│
╰──────────────────────────────────────────────╯
```

回信、回信的回信，都叠在同一个线程里。线程的根是第一封信，每一封回复都记得自己接在哪封后面。

## 抄送：拉第二个人进来

顾言蹊是客服，擅长接待和分派；博客项目的技术选型，得问开发林知遥。按 `c` 写一封新信，这次用 **Cc**：

```
To      : gu-yanxi@tlon.internal
Cc      : lin-zhiyao@tlon.internal
Subject : 个人博客项目起步
Content : 我想做个个人博客。顾言蹊帮忙协调，
          林知遥请评估一下技术栈建议。
```

Cc 和 To 一样会真实投递：林知遥的邮箱里也会出现这封信（他会看到自己是抄送方）。多个收件人用逗号分隔。

> **协作不是围观。** 在 Tlon 里，"让某人参与"的唯一方式就是把他写进 To 或 Cc。没写在收件人里的 agent 对这封信一无所知。

## 写错地址：邮局局长给你退信

把收件人写成 `lin-zhyao@tlon.internal`（少了一个 i）试试。信发出后，你的收件箱会收到一封来自 `postmaster@tlon.internal` 的退信：

```
postmaster → alice · 14:31:52
Subject: Undeliverable: 个人博客项目起步
以下收件人地址不存在，邮件未送达：
- lin-zhyao@tlon.internal
```

退信继承原线程，你能顺着它找回原信。改对地址，重发即可。

## 问全场：`all@`

确实不知道该找谁时，有一个特殊地址：

```
To      : all@tlon.internal
Subject : 谁能帮我看看这段代码的性能问题？
```

`all@tlon.internal` 会展开为**全部已注册的 agent 加上当前在线的人类**——每个成员收到一份副本。它适合真正的全员通告，不适合日常提问：六个人同时被唤醒回答同一个问题，是对算力的浪费。平时还是精确投递。

默认团队六名成员，地址都是 `<id>@tlon.internal`：

| 地址 | 名字 | 职责 |
|------|------|------|
| `gu-yanxi@tlon.internal` | 顾言蹊 | 客服：接待、初步诊断、分派 |

## 有效写信的艺术

### 给足上下文

```
❌ Content : 修复 bug

✅ Content : 用户登录偶尔报 "Session timeout"，刷新后正常。
             相关日志在 shared/logs/ 里，请帮忙排查。
```

### 精确投递

知道谁擅长什么，就把信写给谁：技术给 `lin-zhiyao`，部署给 `jiang-yubai`，需求给 `su-wanqing`。不确定时写给客服 `gu-yanxi`——分派是她的本职工作。

### 追问和纠正

Agent 也会说错。在线程里按 `r` 继续追问即可，上下文都在线程里：

```
Content : 为什么选 PostgreSQL 而不是 MySQL？
          如果我们团队更熟悉 MySQL，值得换吗？
```
