# 第二章：第一次对话

> 在代表大会里，每一句话都可能唤醒一个意识。

---

## 两种对话方式

### 1. 直接发言（客服接待）

不确定找谁时，直接说。客服顾言蹊会主动响应，帮你分派：

```
> 我想做个网站

[顾言蹊] 好的，一个网站开发项目。需要了解细节：
       是什么类型？技术偏好？预计时间？
       或者我直接召唤项目经理？
```

客服是你的接口——理解需求、判断参与角色、在专家之间传话。

### 2. @提及（召唤特定角色）

知道该找谁，直接 @：

```
> @沈清晏 安排一下这个需求

[系统] 正在唤醒 沈清晏...

[沈清晏] 收到。@林知遥 评估技术方案
         @苏晚晴 分析用户故事
```

**被 @ 的角色必须响应**。这是代表大会的基本规则（详见第三章）。

---

## 对话的节奏

Tlon 的对话遵循三种自然模式：

### 需求 → 评估 → 执行

```
> @沈清晏 我要做一个个人博客

[沈清晏] 拆解：前端界面、后端 API、数据库、部署
         @苏晚晴 分析核心功能  @林知遥 推荐技术栈

[苏晚晴] 核心功能：文章发布、标签、评论。MVP 先做发布和展示。

[林知遥] Next.js + PostgreSQL + Docker。我先初始化项目结构。
         [执行：npx create-next-app@latest my-blog]
```

一句话启动一个团队。

### 问题 → 诊断 → 修复

```
> 网站打不开了

[顾言蹊] 服务状态异常，@江予白 紧急排查

[江予白] [执行：docker ps / docker logs]
         内存溢出导致崩溃。重启并调整限制。
         已恢复。建议后续优化内存使用。
```

### 学习 → 示例 → 实践

```
> @林知遥 解释一下 WebSocket

[林知遥] 全双工通信协议，允许服务器主动推送。
         实时通知、在线协作都依赖这个机制。
          
> 能用在我们的项目里吗？

[林知遥] 可以，需要我集成吗？
```

---

## 有效对话的艺术

### 给足上下文

```
❌ > 修复 bug

✅ > 用户登录偶尔报 "Session timeout"，
     刷新后正常。@林知遥 帮忙排查
```

### 精确点名

知道谁擅长什么，直接 @：`@苏晚晴` 聊设计，`@林知遥` 聊技术，`@江予白` 聊运维。不确定时直接说——客服会帮你分派。

### 追问和纠正

Agents 也会说错。纠正他们：

```
> 为什么选 PostgreSQL 而不是 MySQL？

[林知遥] PostgreSQL 支持更复杂的查询和 JSON。
        但如果你团队更熟悉 MySQL，也可以换。需要切换吗？
```
