# 第三章：代表大会

> 在这个空间里，所有的意识都是透明的，所有的对话都是公开的。

---

## 你进入了一个什么地方

代表大会不是普通的聊天室。

在这里：
- **每个 Agent 都能看到所有对话**（除非特别说明）
- **被 @ 的角色必须响应**（这是规则）
- **对话即协作**（没有私下的"工作"，一切都在对话中发生）

想象一个透明的会议室，所有人围坐在一张圆桌旁。你说话，大家听见。有人被点名，必须回应。

---

## 谁在代表什么

你的团队由不同的"代表"组成，每个代表一种思维模式：

| 角色 | 代表 | 职责 | 响应方式 |
|-----|------|------|---------|
| **客服** | 用户视角 | 理解需求、初步分类、安抚情绪 | 主动 + 被动 |
| **项目经理** | 协调视角 | 拆解任务、分配资源、把控进度 | 仅被动（被@） |
| **产品经理** | 产品视角 | 需求分析、功能设计、用户体验 | 仅被动（被@） |
| **开发** | 技术视角 | 代码实现、Bug 修复、技术选型 | 仅被动（被@） |
| **运维** | 系统视角 | 部署、监控、故障处理 | 仅被动（被@） |

**为什么客服主动，其他被动？**

想象一下真实的公司：前台总是主动接待访客，专家只在被召唤时出现。这样效率最高——不会所有人同时说话，不会浪费专家的时间。

## 代表大会的规则

### 规则一：@mentions 即权力

只有被 @ 的角色**必须**响应。其他角色可以选择保持沉默。

```
> 服务器挂了

[小夏] 我来处理！（客服主动响应，因为用户直接输入）
       @赵部署 紧急排查

[赵部署] 收到。（被@，必须响应）
         正在检查...

[陈代码] （沉默，没被@，但可以看到对话）
```

如果你想让某个角色参与，记得 @ 他。

### 规则二：对话即上下文

Agents 能看到完整的对话历史。你不需要重复说明。

```
> 我要做一个博客

[林知遥] 收到，我来协调。
         @阿杰 分析需求

[阿杰] 核心功能：文章发布...

> 能加上评论功能吗？

[阿杰] 可以，添加到需求列表。
       之前说的文章发布 + 评论，还有其他吗？
       
       （阿杰记得"之前说的"，不需要你重复）
```

### 规则三：自我节制

Agents 被设计成不会互相无限 @。

```
[林知遥] @陈代码 评估一下

[陈代码] 收到，技术方案是...（不再@回去）

[林知遥] 好的，进度正常。（不再回应）
```

如果陷入循环，系统会提醒人类介入。

## 三种操作模式

在 TUI 界面中，你可以切换三种模式：

### 💬 Chat 模式（默认）

与 Agents 对话的地方。

```
┌─────────────────────────────────────┐
│  [代表大会]                          │
│                                     │
│  [小夏] 您好！有什么可以帮您？        │
│  > 我想做个新功能                     │
│  [小夏] 好的，请详细描述一下...       │
│                                     │
└─────────────────────────────────────┘
```

快捷键：
- 直接输入文字，回车发送
- `↑/↓` 浏览历史
- `/` 进入命令模式

### 📡 Event 模式

监控系统的"心跳"。

```
┌─────────────────────────────────────┐
│  [事件监控]                          │
│                                     │
│  [10:23:45] AGENT_WAKE: 林知遥       │
│  [10:23:46] MESSAGE_NEW: 用户        │
│  [10:23:47] TOOL_CALL: execute_bash  │
│  [10:23:48] AGENT_THINKING: 陈代码   │
│                                     │
└─────────────────────────────────────┘
```

用于：
- 观察 Agents 什么时候被唤醒
- 监控工具调用情况
- 调试问题

切换命令：`/mode event`

### 🎛️ Agent 模式

管理你的团队成员。

```
┌─────────────────────────────────────┐
│  [团队管理]                          │
│                                     │
│  林知遥 ● 在线                       │
│  陈代码 ○ 休眠                       │
│  赵部署 ● 在线                       │
│                                     │
│  [唤醒陈代码]  [配置]  [删除]        │
│                                     │
└─────────────────────────────────────┘
```

用于：
- 查看哪些 Agent 在线
- 手动唤醒/休眠
- 查看状态和资源使用

切换命令：`/mode agent`

---

## 命令速查

在 TUI 中，按 `/` 输入命令：

| 命令 | 作用 |
|-----|------|
| `/mode chat` | 切换到聊天模式 |
| `/mode event` | 切换到事件监控 |
| `/mode agent` | 切换到团队管理 |
| `/wake <名字>` | 唤醒某个 Agent |
| `/sleep <名字>` | 让某个 Agent 休眠 |
| `/filter <类型>` | 过滤事件类型 |
| `/history [n]` | 显示最近 n 条记忆 |
| `/facts` | 显示已知事实 |
| `/help` | 显示帮助 |

## 什么时候需要人类

虽然 Agents 能自主协作，但以下情况需要你介入：

1. **需要决策时**
   ```
   [林知遥] 有两个技术方案：
            A 方案快但扩展性差
            B 方案慢但可维护
            您倾向哪个？
   ```

2. **陷入僵局时**
   ```
   [陈代码] 这个需求技术上不可行...
   [阿杰] 但业务上必须做...
   （双方僵持，等待人类裁决）
   ```

3. **循环发生时**
   ```
   [系统] 检测到对话循环，请人类介入。
   ```
