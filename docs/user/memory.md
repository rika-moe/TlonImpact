## 两层记忆

想象一个人类的大脑：

### 第一层：此刻的意识

**Working Memory（工作记忆）**

就像你正在进行的对话——最近说的几句话，还记得很清楚。

- 容量：最近 10 次交互
- 内容：完整的对话、工具调用、执行结果
- 清空时机：总结后归档，或重启系统

### 第二层：一生的经验

**Episodic Memory（情节记忆）**

就像你的长期记忆——过去的重要事件、学到的教训、形成的偏好。

- 容量：无限制（文件存储）
- 内容：
  - **摘要**：过去会话的总结
  - **事实**：结构化记录（偏好、决策、项目状态）

---

## 记忆是如何工作的

### 场景一：即时回忆

```
> 继续优化昨天那个 API

[林知遥] 好的，昨天的 API 响应时间是 200ms。
         我尝试了几种缓存策略，
         Redis 方案效果最好，能降到 50ms。
         
         今天要进一步优化吗？
         
         （不需要你提醒"哪个 API"、"做了什么"）
```

### 场景二：跨会话记忆

**三天前的对话：**
```
> 我喜欢 Material Design 的风格

[苏晚晴] 收到，记录偏好。
```

**今天的对话：**
```
> 写信给 苏晚晴：设计一下登录页面

[苏晚晴] 好的。根据你之前的偏好，
       我采用 Material Design 风格，
       圆角、阴影、简洁的配色。
       
       这是原型...
       
       （记得你三天前随口说的一句话）
```

### 场景三：事实提取

```
> 写信给 沈清晏：项目进度如何？

[沈清晏] 根据已知信息：
         - 后端 API：已完成 80%（林知遥负责）
         - 前端页面：已完成 60%（林知遥负责）
         - 部署环境：已就绪（江予白负责）
         
         预计本周五可交付 MVP。
         
         （这些不是实时统计，是记忆中记录的状态）
```

## 记忆的自动管理

### 触发摘要的时机

系统会自动将工作记忆转化为长期记忆：

1. **数量触发**：Working Memory 满 10 条
   ```
   [系统] 会话即将归档...
          [沈清晏] 正在生成摘要...
          已保存到情节记忆。
   ```

2. **时间触发**：空闲 30 分钟
   ```
   （你离开半小时后回来）
   
   [系统] 已自动生成上次会话摘要。
   ```

3. **手动触发**：
    ```
    > 帮我把今天的讨论总结一下
    
    [沈清晏] 正在生成摘要...
            已保存到情节记忆。
    ```

### 记忆的组织形式

**摘要示例：**
```
[2024-03-09] 博客项目启动会议
- 需求：个人博客系统
- 技术栈：Next.js + PostgreSQL + Docker
- 分工：
  - 林知遥：后端 API
  - 林知遥：前端界面
  - 江予白：CI/CD
- 决策：采用 Material Design 风格
- 截止日期：3月15日
```

**事实示例：**
```
用户偏好：
- 前端框架：React > Vue
- UI 风格：Material Design
- 配色：深色模式

项目状态：
- 博客项目：进行中，60%完成
- 爬虫工具：已完成

重要决策：
- 数据库选择 PostgreSQL（原因：复杂查询支持）
```

## 你可以主动管理记忆

### 通过对话管理

直接写信给 Agent 即可——记忆操作是 Agent 的内置能力：

```
> 写信给 林知遥：记住，以后所有项目都用 TypeScript

[林知遥] 已记录：用户偏好 TypeScript。
        将在后续项目中默认使用。
```

查看和删除同样通过写信：

```
> 我们上次讨论的 API 方案是什么？

[林知遥] 根据记忆，上次讨论的 API 方案是 REST + JSON:API 规范，
        响应时间目标 <200ms。

> 写信给 林知遥：忘掉 TypeScript 那条

[林知遥] 已删除相关记忆。
```

### 触发归档

要求 Agent 生成会话摘要：

```
> 帮我把今天的讨论总结一下

[沈清晏] 正在生成摘要...
        已保存到情节记忆。
```

Agent 拥有 `compact` 工具，你随时可以要求归档。

## 记忆的局限

### 不是完美的

1. **容量限制**
   - Working Memory 只有 10 条
   - 如果会话太长，早期的细节会丢失（但摘要在）

2. **理解偏差**
   - Agent 可能"记错"你的意思
   - 重要信息建议明确确认

3. **隐私边界**
   - 记忆存储在本地文件（`~/.tlon/{agent-id}/memory/`）
   - 删除 Agent 时可选择是否删除记忆

### 最佳实践

✅ **明确表达偏好**：
```
> 记住，我不喜欢 Bootstrap
```

✅ **确认重要决策**：
```
> 所以我们决定用 PostgreSQL，对吗？

[沈清晏] 确认。已记录决策。
```

✅ **定期整理**：
```
> 总结一下最近的进展  # 触发归档
> 我们之前讨论了哪些关键决策？  # 核对记忆准确性
```

---

## 删除记忆

如果你想"重置"某个 Agent 的记忆，写信要求即可：

```
> 写信给 顾言蹊：清空你关于我的所有记忆

[顾言蹊] 确认：将清空所有会话摘要和记录的事实。
       我的角色定义不变。是否继续？
```

这会清空：
- 所有会话摘要
- 所有记录的事实
- Working Memory

**但保留**：Agent 的角色定义（名字、性格）。

相当于"失忆重生"，不是"死亡"。
