# 第三章：代表大会

> 在这个空间里，所有的意识都是透明的，所有的对话都是公开的。

---

## 你进入了一个什么地方

代表大会不是普通的聊天室。

在这里：
- **每个 Agent 都能看到所有对话**（除非特别说明）
- **被 @ 的角色必须响应**（这是规则）
- **对话即协作**（没有私下的"工作"，一切都在对话中发生）

想象一个透明的会议室，所有人围坐在一张圆桌旁。你说话，大家听见。有人被点名，必须回应。

---

## 谁在代表什么

你的团队由不同的"代表"组成，每个代表一种思维模式：

| 角色 | 代表 | 职责 | 响应方式 |
|-----|------|------|---------|
| **客服** | 用户视角 | 理解需求、初步分类、安抚情绪 | 主动 + 被动 |
| **项目经理** | 协调视角 | 拆解任务、分配资源、把控进度 | 仅被动（被@） |
| **产品经理** | 产品视角 | 需求分析、功能设计、用户体验 | 仅被动（被@） |
| **开发** | 技术视角 | 代码实现、Bug 修复、技术选型 | 仅被动（被@） |
| **运维** | 系统视角 | 部署、监控、故障处理 | 仅被动（被@） |

**为什么客服主动，其他被动？**

想象一下真实的公司：前台总是主动接待访客，专家只在被召唤时出现。这样效率最高——不会所有人同时说话，不会浪费专家的时间。

## 代表大会的规则

### 规则一：@mentions 即权力

只有被 @ 的角色**必须**响应。其他角色可以选择保持沉默。

```
> 服务器挂了

[顾言蹊] 我来处理！（客服主动响应，因为用户直接输入）
       @江予白 紧急排查

[江予白] 收到。（被@，必须响应）
         正在检查...

[林知遥] （沉默，没被@，但可以看到对话）
```

如果你想让某个角色参与，记得 @ 他。

### 规则二：对话即上下文

Agents 能看到完整的对话历史。你不需要重复说明。

```
> 我要做一个博客

[沈清晏] 收到，我来协调。
         @苏晚晴 分析需求

[苏晚晴] 核心功能：文章发布...

> 能加上评论功能吗？

[苏晚晴] 可以，添加到需求列表。
       之前说的文章发布 + 评论，还有其他吗？
       
       （苏晚晴记得"之前说的"，不需要你重复）
```

### 规则三：自我节制

Agents 被设计成不会互相无限 @。

```
[沈清晏] @林知遥 评估一下

[林知遥] 收到，技术方案是...（不再@回去）

[沈清晏] 好的，进度正常。（不再回应）
```

如果陷入循环，系统会提醒人类介入。

> ⚠️ 循环检测功能尚未实现。当前两个 Agent 互相 @ 不会自动终止，需要你手动介入。这是 M7 之后的规划功能。

## Congress TUI 界面

启动 Congress 后，你会看到一个**单栏聊天界面**——像微信一样的极简设计：

```
┌─────────────────────────────────────────────────┐
│  █ Header                           🕐 14:23    │
├─────────────────────────────────────────────────┤
│  💬 Congress              在线: 3/3     已连接   │
├─────────────────────────────────────────────────┤
│                                                 │
│         [系统] 沈清晏 已加入代表大会              │
│  [顾言蹊] 您好！我是客服顾言蹊，有什么可以帮您？      │
│                            > 我想做个新功能       │
│  [顾言蹊] 好的，请详细描述一下...                  │
│                                                 │
├─────────────────────────────────────────────────┤
│ [🤖 ▼] │  输入消息...                   [发送]   │
└─────────────────────────────────────────────────┘
```

三个关键元素：

| 区域 | 功能 |
|------|------|
| **顶部条** | 标题 "💬 Congress"、在线 Agent 数、连接状态 |
| **消息区** | 你的消息右对齐（蓝色气泡），Agent 消息左对齐（带头像），系统消息居中 |
| **输入区** | 文本输入框 + Agent 下拉选择器 + 发送按钮 |

### Agent 选择器

输入区左侧的下拉菜单，可选择 **@ 某个 Agent** 或 **@All（所有人）**：

```
┌──────────┐
│ 🤖 ▼    │
├──────────┤
│ 🟢 @顾言蹊  │  ← 空闲
│ 🔵 @沈清晏│  ← 活跃
│ ⚪ @林知遥│  ← 离线
│──────────│
│ @All     │  ← 通知所有人
└──────────┘
```

### @Mention 自动补全

输入 `@` 自动弹出 Agent 列表，支持模糊搜索。选中的 Agent 会被 @ 并保证响应。

## 命令速查

按 `/` 打开命令面板：

| 命令 | 作用 |
|-----|------|
| `/clear` | 清空当前对话 |
| `/agents` | 查看 Agent 列表及状态 |
| `/help` | 显示帮助信息 |
| `/quit` | 退出 Congress |

**快捷键**：

| 按键 | 操作 |
|------|------|
| `Tab` | 循环切换 Agent |
| `Enter` | 发送消息 |
| `Esc` | 关闭弹窗 / 退出 |
| `↑` / `↓` | 浏览输入历史 |
| `/` | 打开命令面板 |
| `Ctrl+C` | 退出程序 |

## Operator：工程师的控制台

Congress 专注于对话。需要**事件监控、Agent 管理、日志查看**时，使用 Operator TUI：

```bash
uv run tlon ops
```

Operator 提供五个标签页：Agents（团队状态）、Events（系统事件流）、Logs（执行日志）、Traces（调用链路）、Config（配置查看）。详见 [命令参考](../engineering/commands.md)。

## 什么时候需要人类

虽然 Agents 能自主协作，但以下情况需要你介入：

1. **需要决策时**
   ```
   [沈清晏] 有两个技术方案：
            A 方案快但扩展性差
            B 方案慢但可维护
            您倾向哪个？
   ```

2. **陷入僵局时**
   ```
   [林知遥] 这个需求技术上不可行...
   [苏晚晴] 但业务上必须做...
   （双方僵持，等待人类裁决）
   ```

3. **循环发生时**
    ```
    [沈清晏] @林知遥 评估一下
    [林知遥] @沈清晏 需要更多信息
    [沈清晏] @林知遥 先按现有信息评估
    [林知遥] @沈清晏 我重新问一下...
    （双方反复 @，需要你拍板）
    ```
