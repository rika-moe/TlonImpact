# 记忆、执行记录与工作上下文

长期记忆是成员自行维护的普通私有文件。成员通过现有文件工具决定是否查阅、记录、修改或整理笔记；运行时不自动提炼、检索或注入记忆，不调用模型替成员维护记忆。允许一个 run 完全不读取记忆，也允许完成工作后不更新记忆。

这项决策取代此前 journal → claims 自动蒸馏、向量检索注入、冲突裁决、周期反思和退休自动教训蒸馏。旧模型的历史设计见 ADR 0017；当前实现不提供旧 claims、索引和维护 checkpoint 的兼容读取或迁移，也不删除用户已有归档。

## 三种数据

| 数据 | 用途 | 权威与生命周期 |
| --- | --- | --- |
| 原始执行记录 | 查证输入、模型响应、工具效果、失败与额度 | ProgramStore 保存执行事实；笔记修改不改变回执。`run-read` 只读回查，恢复仍由运行时负责。 |
| 长期记忆 | 选择性保留偏好、决定、发现和经验 | 成员自己使用普通文件工具维护 workspace 下的笔记；可以遗漏、修订或不写。 |
| 工作上下文 | 让当前模型调用完成任务及在后续 run 延续 | Lisp 工作流组装消息、保持 run 内 append-only，并在边界准备上下文交接。摘要不自动写成长期记忆。 |

可靠任务进度、已提交效果和额度不能依赖成员是否写笔记；仍由 ProgramStore、任务状态及显式 checkpoint 保存。笔记属于数据，不因写入而成为 system 指令或执行回执。

## 私有文件与工具

建议在成员持久 workspace 中使用 `memory/` 目录，例如 `memory/index.md`、`memory/preferences.md`、`memory/project-a.md`。目录、索引、格式和文件拆分都是可选约定，不是运行时 schema；不强制创建空目录或索引，不把目录内容自动装进提示词。

- `file-list` / `file-search`：浏览或搜索自己的笔记。
- `file-read`：分段读取，结果作为普通工具消息追加。
- `file-write` / `file-edit`：明确创建、覆盖或局部修改文件。
- `run-read`：需要核查笔记时回读自己的执行来源；笔记可记录 run ID 或 mail ID。

复用已有 workspace 路径隔离、读写边界和持久工具回执；访问自己的 workspace 不依赖 Docker。不能通过绝对路径或符号链接越界访问其他成员，也不能编辑原始 program 数据库。文件写结果未知时沿用普通文件操作的恢复规则，不把它当作成功或自动重写。

文件搜索采用现有文件名匹配与正文检索，不提供专门的语义搜索、embedding、claim 生命周期或自动冲突处理。需要整理或解决矛盾时由成员明确执行，必要时组合普通 Lisp 程序和模型调用；不另建 Python 记忆工作流。

## 提示词与缓存

系统提示词仅提供稳定的文件位置与工具使用约定，说明读写均可选。记忆正文、索引和检索结果不自动注入任何消息角色。普通工作流也不在每个 run 前后强制调用文件工具。

笔记变化不会自行改变 system prompt 或已有消息前缀。成员显式读取时，文件内容以工具结果追加；同一 run 的已有消息不随磁盘变化而重写。读取仍有工具往返和 token 成本，缓存命中率不能替代实际用量、延迟与行为质量指标。

## 行为与验证

正确性关注：无记忆读写也能完成邮件任务；有需要时能通过文件工具读写，重启后保留；成员相互隔离；修改笔记不自动改变模型上下文；工具结果和来源可查，未知效果不重复执行。没有“每个 run 必须产生记忆”的完成门槛。

原有自动蒸馏评测不再适用。使用普通文件工具与标准 agent 的回归和集成测试，验证可选读写、持久化、隔离与提示词稳定性；模型是否选择了有用笔记属于 agent 行为质量，不能伪装成存储系统的必然保证。

## 与退休和传承的关系

退休仍可只读清点未完成任务、待回复邮件和已有笔记文件。停止成员后不再以其身份自动调用模型提炼教训。将经验整理为笔记、起草下一代的 `LESSONS.md` 或原型，应在普通成员程序中显式完成，并沿用已有原型提交与审核流程。

## 上下文压缩边界

本次更改只替换长期记忆机制，保留现有 Lisp 连续消息与边界 handoff 行为，不新增上下文压缩算法或跨 run 未完成任务协议。完整执行事实、可编辑笔记和有损工作摘要各有独立用途，不能相互替代。
