## H1：一个标准程序跨邮件继续，闭合持久与恢复边界

**范围**：先实现标准 short-turn 的主历史。沿用 ProgramStore 私有 state 与成员串行入口；普通模块保存完整消息组、待完成调用和有效提示快照。跨事件复用 system/tools/非秘密模型配置，同时保留每事件独立预算。覆盖外层自动回信和标读，不只保存内部 model/tool 循环。

重点核对 `operations/state.py`、`agents/program_store.py`、`agents/member_runtime.py`、`agents/program_driver.py`，以及 `stdlib/agent.tlon`、`conversation.tlon`、`messages.tlon`。在原执行/状态边界补齐来源身份、旧写保护、运行终态与回执引用；只读投影已有信息优先复用。若必须新增端口，仅提供通用事实读取或状态原子条件写，不新增会话驱动器。明确区分目前 state-put 的原子性和计划新增保证。

确定失败由普通程序读取原事实补齐后释放历史；unknown、身份失配与损坏状态阻塞主历史推进。普通模型工具不能改写程序拥有的历史键。初始版本窗口不足明确拒绝；显式提示配置应用尚未提供时，只展示待生效差异并拒绝应用，不自动读取新配置改前缀。

**验收**：

- 两封不同发件人的邮件进入同一历史，无配置变更时第二封请求延续第一封完整消息；系统/工具序列化结果相同，没有从邮箱再次导入旧邮件。
- 重启、休眠唤醒后继续；重复投递事件不重复追加或发信。每封事件独立预算，旧根不充值，历史静置不阻止排空。
- 故障注入覆盖输入保存前后、模型响应提交后、工具部分成功、工具全成功但保存前、自动回信后、标读后、保存后完成前；断言 provider/工具/发信次数与账本不重复。
- 明确失败保留确定进展，新事件可继续；unknown 后新邮件留在邮箱且不推进历史，不能借新根再执行旧效果。损坏历史保留字节并可诊断。
- 冻结目录不绕过当前授权；直接调用 state-put 不能覆盖程序历史。配置文件变化只显示待生效，不改变下一封邮件前缀。
- 隔离 dream + SDK + 真实模型，连续邮件、修改 CONTACTS.md、重启后再来信；核对实际模型请求、文件新值、收件箱与独立预算根。

**删除项**：short-turn 路径按邮件重建 member-context/mail_history/recap 的代码，以及依赖旧重建行为的断言。保留 member-context、session-read 等仍有调用方的通用查询，不因默认策略不用就整项删除。

## H2：审计并修正内置工作程序的历史连续性

**范围**：审计并修正现有内置工作方式和原型中的历史丢失、错误重建与事实遗漏，保留各自流程实现。梳理 `agent.tlon`、`workflows.tlon`、`conversation.tlon` 与随包 examples/prototypes；分别核对计划、核验、修订、finish-turn、工具发信和外层发信的保存边界，不要求调用同一个标准循环或历史管理函数。更新原型源码、digest、播种及打包验证。

评审临时请求可使用独立工具集，但实际采用内容追加进主历史，并注明来源；原始模型建议与实际执行参数保留对应关系。修正无意退回旧 history 或丢弃 prepared messages 的路径；临时核验请求可自行选取相关材料，不要求复制完整主历史。失败整理使用原运行事实，不能把普通失败当成再次生成的许可。

**验收**：

- 每种内置工作方式连续处理多封不同主题邮件，主历史不被误丢、重复导入或意外重建；允许有明确用途的临时分支上下文。
- 保留不同循环和流程实现；新增一个不依赖标准循环的自定义 workflow，用相关材料构造核验请求后仍能追加采用结果、正确恢复并遵守预算，证明标准库没有成为必经入口。
- 原建议、修订意见与投递结果可对账；失败工具不算成功发信；已成功投递不触发外层重复回信。
- finish-turn 只结束当前工作，不清历史或擅自睡眠；轮数耗尽保存失败事实，不静默标成成功。
- 重复 H1 的关键崩溃窗口，覆盖计划/核验支线和修订后投递；真实冒烟覆盖计划执行及评审修订。
- 所有内置原型 digest 和打包源码验证通过；新工作方式不新增宿主 stage。

**删除项**：其余标准程序和原型中旧的每邮件拼装、滑动邮箱/recap 默认注入、丢弃 prepared history 的分支。不以重复代码或循环实现不同为删除理由，不删除自定义上下文构造、不同工作方法及仍用于历史回读或维护的通用领域能力。

## H3：持久化批量压缩，控制长期增长

**范围**：改造普通 `tlon.context`，按完整交互组批量压缩，保留稳定前缀、当前任务与近期组，并为后续交换留出空间。压缩视图与来源范围作为普通状态保存；原始模型/工具回执不删除。主历史后续延续保存的压缩结果；各工作程序仍可自行选材构造模型请求，并遵守窗口、协议和预算。

**验收**：

- 无压力时零压缩请求，逐封邮件只追加；压缩一次后后续事件不重复总结同一来源。
- 摘要调用已提交但状态未保存时恢复不重调模型；压缩失败保留旧视图，预算耗尽不换根。
- 工具组不可拆，当前未完成任务、失败、不确定性和来源均保留；单组超窗明确拒绝。
- 在明确记录的模型窗口和工具结果大小下，压缩后可继续完成至少一轮模型/工具交换，避免立即重复压缩；不声称对任意大工具结果都能保证空间。
- 真实模型长历史冒烟触发压缩后仍可回答跨邮件任务；记录压缩调用量、输入体积和缓存字段，未提供字段时标未知。

**删除项**：用于主历史的逐旧组一次摘要调用、每事件重新压缩同一范围的行为，以及把摘要当回执的断言。若通用 compact 实现被整体替换，调用方一起更新，不留两套默认策略。

## H4：显式应用配置与发布收口

**范围**：复用现有成员配置/管理通道，支持检查有效快照与待生效差异，并在事件之间显式应用。人格、工具 schema、模型请求配置变化不再隐式改下一事件前缀。授权撤销实时生效，凭据不入历史，预算仍独立取当前事件约束。新模型/目录应用前验证现有历史；合法时保留消息并追加变更事实，必要压缩受明确操作及预算约束。

配置应用与新事件受理共享成员串行边界：已受理事件不被半途修改；应用成功后的下一事件冻结新快照。控制操作本身不创建永久会话根，若需模型压缩则有明确有限维护根和额度，不借用已结束事件的预算。非模型应用不得隐式派发模型请求。

**验收**：

- 修改文件后连续来信仍使用旧有效提示；显式应用后才切换，历史保留、变更可见、允许该边界缓存失效。
- 应用与邮件并发及进程中断测试证明只有完整旧/新快照，没有半配置；幂等重复提交不重复追加变更。
- 模型协议、窗口或工具消息不兼容时明确拒绝应用，旧有效快照与待生效差异可查；不提供迁移、静默清空或兼容 fallback。
- 授权撤销立即阻止真实调用，即使冻结工具仍在；凭据轮换不暴露秘密、不隐式切模型。
- 对照相邻实际请求，分别列出普通追加、压缩、显式配置应用造成的前缀差异；真实冒烟验证配置切换前后任务仍连续。
- 同步 architecture、runtime、指南、reference 与原型说明；未完成项不标已实现。

**删除项**：新邮件自动重建宿主 system/tools 的旧策略、临时拒绝显式应用的限制、已无人使用的旧拼装辅助代码与文档。只删经调用审计确认无用的实现，不引入旧状态转换器。

## 各阶段发布与最终验收

每阶段运行 `scripts/check_all.sh` 全量质量门，审 diff，并执行对应隔离 dream + SDK + 真实模型冒烟，核对 SQLite 收件箱和 ProgramStore，清理进程、临时数据与端口。失败不得靠增加超时或删有效语义断言解决。测试使用可控时钟和明确后台任务边界，避免维护 tick 干扰计数。

最终证据包括：所有邮件进入一段主历史；常规事件只追加；明确保存点与全故障窗口恢复；每事件独立额度；压缩可持久复用；显式配置生效；未知结果阻塞且不丢邮件；无新 Session 引擎。缓存报告保留输入量、provider 用量字段和正确性证据，不设置无法保证的命中率门槛。

本次仅落设计文档，不创建实现、兼容层或新运行数据；各阶段 PR/Issue 后续记录实际施工证据。本计划的验收清单不是已完成声明。
