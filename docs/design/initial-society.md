# 首启初始社会

决策依据：[ADR 0036](../decisions/0036-initial-society.md)。全新实例首次运行 `tlon dream` 时创建 30 位初始人物；安装 Python 包本身不操作用户数据目录。初始化在 ConfigService 读取成员前完成，不发送邮件、不调用 LLM。

## 包内资料与实例数据

`src/tlon/initial_society/` 随 wheel/sdist 提供人物清单、思想背景、45 条双向认识关系，以及每位的中文 IDENTITY.md、SOUL.md、RULES.md。资源来自此前编写的初始稿，不复制运行中的 ~/.tlon。

人格职责见 [identity](identity.md)：IDENTITY 是自我定义与初始归属，SOUL 是价值观、性格、表达和判断倾向，RULES 是工作规则与流程。自己的 `workspace/CONTACTS.md` 在实例创建时生成，包含联系人名字、简短思想背景、新实例的真实地址；联系簿正文不注入系统提示，由成员用普通文件工具按需读取和修改。普通联系不虚构既往通信，同组织伙伴明确初始合作约定。

每位先分配新的 m-UUID，再解析关系。图有 30 个节点、45 条无向边，实际联系簿双向记录，共 90 个条目；每位 2–4 个联系人，整图连通。种子键只用于包内资料关联，不是成员地址，不承载认证身份。

## 创建与生命周期

bootstrap 先播种现有内置行为原型、技能，再初始化成员。全部成员复用“标准工具迭代”原型（L2），模型明确写入各自的 `agent.yaml`：`deepseek/deepseek-flash`，top_p=0.9；单次输出按模型能力、剩余上下文和 run 剩余预算决定。其余部署设置沿用 AgentConfig 的默认值。API key 仍由用户在实例 `.env` 配置，不打包密钥；手工创建其他成员仍需明确选择模型。

`initial-society.json` 保存计划与完成/跳过状态，`initial-society-lock.sqlite3` 用 SQLite 事务互斥，`.initial-society-staging/` 暂存完整成员。首次创建保存完整地址计划，暂存完整成员后发布，最后记录完成状态。初始化锁避免同一实例并发创建；状态损坏直接报错。中断后继续原计划，已经发布的成员文件不覆盖。完成后重启或升级不再创建、补回或覆盖成员。

已有成员配置（包括无效配置）、成员持久状态、共享邮件数据库或 WebUI 身份的实例跳过初始成员。不会对已有社会追加 30 位，也不会把当前实例的经历纳入安装包。

## 验证边界

单元测试覆盖资源完整性、图结构、地址解析、首次创建、二次启动、删除后重启、已有实例、中断恢复与损坏状态；集成测试在临时 TLON_HOME 初始化真正 runtime/ServerApp。打包验证检查清单与 30 位人物的全部三文件。实际 dream 与 HTTP 冒烟使用临时实例、无外部模型密钥，验证投信入箱后停止服务并清理。
