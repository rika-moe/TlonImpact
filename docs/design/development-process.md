# 开发流程规范

> 状态: ✅ 已验证
> 最后验证: 2026-03-17

---

## 核心理念

1. **文档先行**: 设计必须在文档中明确后才可实施
2. **禁止提前实施**: 讨论阶段不得修改代码
3. **小步快跑**: Roadmap 的 task 要足够小，方便回溯
4. **及时同步**: 完成每个 task 后更新进度

---

## 四阶段流程

### 阶段一：方案讨论（⚠️ 禁止修改文件）

1. 首先与用户讨论设计方案
2. 使用提问、建议、对比方案等方式深入理解需求
3. **在用户明确批准设计方案之前，不得修改任何文件**

### 阶段二：文档化（✅ 可以写文档）

1. 用户批准设计方案后
2. 将方案写入 `docs/` 目录下的适当位置

### 阶段三：等待实施指令（⚠️ 禁止写代码）

1. 在**用户明确说"开始实施"之前**，不得编写代码
2. 可以继续讨论、澄清、完善文档

### 阶段四：实施（✅ 开始编码）

1. 用户说"开始实施"之后
2. **先撰写开发路线图**：创建 task list
3. **按 roadmap 逐步实施**：
   - 每次完成一个 task
   - 完成后更新 roadmap 状态
   - 如有需要，与用户确认下一步

---

## 流程示例

```
用户：我想添加一个新功能 X

我：讨论方案 A、B、C 的优劣...
     你觉得哪个方向更好？

用户：选方案 B，但要做这些调整...

我：确认一下，方案 B 的调整后是：1...2...3...
     对吗？

用户：对的，批准这个方案

[我：写文档 docs/design/features/x-design.md]

我：方案已文档化，等待实施指令

用户：开始实施

[我：创建 roadmap]
[我：按计划逐步实施每个 task]
```
