# 便携实例的模型配置

依据 [ADR 0053](../decisions/0053-portable-windows-distribution.md)。仅便携入口显式启用；普通 CLI 的 WebUI 不要求此向导，也不开放配置写入。

身份沿用现有实例身份流程。其后 WebUI 读取 `/admin/llm/setup`，未完成配置时先显示服务商、模型、API Key 和连接验证。设置页复用同一表单。向导默认选择 DeepSeek 的 `deepseek/deepseek-flash`，与初始社会一致。首版支持 DeepSeek、OpenAI、Anthropic 和 Gemini 的托管服务；模型可从现有目录选择或填写，但必须能通过现有模型能力解析与实际连接验证。

首次应用范围来自初始社会已持久化的真实成员地址，不按“当前所有成员”推断。首次完成后永久禁用整体初始范围；`initial_allowed` 与当前凭据是否可用分开记录，完成标记损坏、Key 文件丢失或环境冲突都不能重新授权批量范围。凭据修复允许 selected 空列表只更新 Key，不要求变更任何成员模型。设置页必须明确勾选要改变模型的成员，不勾选仅更新该服务商的 Key。托管模型选择清除所选成员原来的私有 endpoint 和模型能力覆盖值，重新按所选模型解析，其他成员不变。

保存流程由实例级异步锁串行执行：

1. 验证请求值、模型能力、范围和成员存在性。
2. 使用显式 API Key 向所选模型发送简短请求，尚不修改当前进程环境。
3. 验证成功后原子更新 `data/.env`，同步更新进程环境；成员的新模型逐个写入各自 `agent.yaml` 并经现有 adopt 刷新配置缓存。
4. 首次配置复用现有成员 wait 操作，等待所选成员在启动锁保护下排空旧实例；忙碌成员尚未排空时明确要求重试，不写完成标记。不会将已启动成员的旧模型误判为新模型。
5. 全部完成后写入 `data/model-setup.json` 非敏感完成标记；标记不含模型默认值或凭据。部分失败保留已经成功的写入并明确报错，可重试，不假称完整成功。

API Key 在后续请求生效，无需重启。现有 adopt 不替换驻留成员的 LLMClient；响应与界面明确提示这些成员下次启动才切换模型，可托盘退出后重开 Tlon。初始成员可能已由启动流程装配，首次配置必须先刷新配置并排空这些旧实例，后续邮件才以所选模型重新装配。不引入进程级统一模型或新的运行时热更机制。

Key 不回传、不写日志；连接失败返回固定错误，不透传服务商异常内容。输入拒绝换行、控制字符和 dotenv 插值语法。API 继续受回环地址、同源检查和 `X-Tlon-WebUI` 边界保护。文件未加密，复制整个实例目录也会复制凭据，页面明确说明这一点。

测试覆盖初始 30 人真实配置、缺失凭据与重入、显式选择范围、部分失败重试、并发更新、同源边界，以及真实 LiteLLM 请求本地 HTTP 模拟服务的成功与错误脱敏；这些检查不替代真实外部模型和 Windows 发行包人工验收。
