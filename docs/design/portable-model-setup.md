# WebUI 模型配置

最初依据 [ADR 0053](../decisions/0053-portable-windows-distribution.md) 为便携版实现，现已推广到全部本机 WebUI 启动入口，见下方通用配置规则。

身份沿用现有实例身份流程。其后 WebUI 读取 `/admin/llm/setup`，未完成配置时先显示服务商、模型、API Key 和连接验证。设置页复用同一表单。向导默认选择 DeepSeek 的 `deepseek/deepseek-flash`，与初始社会一致。首版支持 DeepSeek、OpenAI、Anthropic 和 Gemini 的托管服务；模型可从现有目录选择或填写，但必须能通过现有模型能力解析与实际连接验证。

首次应用范围来自初始社会已持久化的真实成员地址，不按“当前所有成员”推断。首次完成后永久禁用整体初始范围；`initial_allowed` 与当前凭据是否可用分开记录，完成标记损坏或凭据失效都不能重新授权批量范围。凭据修复允许 selected 空列表只更新 Key，不要求变更任何成员模型。设置页必须明确勾选要改变模型的成员，不勾选仅更新该服务商的 Key。托管模型选择清除所选成员原来的私有 endpoint 和模型能力覆盖值，重新按所选模型解析，其他成员不变。

保存流程由实例级异步锁串行执行：

1. 验证请求值、模型能力、范围和成员存在性。
2. 使用显式 API Key 向所选模型发送简短请求，尚不修改当前进程环境。
3. 验证成功后原子更新 实例的 `.env`，同步更新进程环境；成员的新模型逐个写入各自 `agent.yaml` 并经现有 adopt 刷新配置缓存。
4. 首次配置复用现有成员 wait 操作，等待所选成员在启动锁保护下排空旧实例；忙碌成员尚未排空时明确要求重试，不写完成标记。不会将已启动成员的旧模型误判为新模型。
5. 全部完成后写入 实例的 `model-setup.json` 非敏感完成标记；标记不含模型默认值或凭据。部分失败保留已经成功的写入并明确报错，可重试，不假称完整成功。

API Key 在后续请求生效，无需重启。现有 adopt 不替换驻留成员的 LLMClient；响应与界面明确提示这些成员下次启动才切换模型，可重启 Tlon。初始成员可能已由启动流程装配，首次配置必须先刷新配置并排空这些旧实例，后续邮件才以所选模型重新装配。不引入进程级统一模型或新的运行时热更机制。

Key 不回传、不写日志；连接失败返回固定错误，不透传服务商异常内容。输入拒绝换行、控制字符和 dotenv 插值语法。API 继续受回环地址、同源检查和 `X-Tlon-WebUI` 边界保护。文件未加密，复制整个实例目录也会复制凭据，页面明确说明这一点。

测试覆盖初始 30 人真实配置、缺失凭据与重入、显式选择范围、部分失败重试、并发更新、同源边界，以及真实 LiteLLM 请求本地 HTTP 模拟服务的成功与错误脱敏；这些检查不替代真实外部模型和 Windows 发行包人工验收。

## 通用 WebUI 配置（取代便携入口限定）

所有 ServerApp 启动入口都提供同一个模型配置服务，不再保留 portable_setup 开关。首次未配置模型时由网页引导；设置页始终可更新凭据及明确选中的成员。文件写入仍使用实例注入的 TlonPaths：便携版为 data/.env，普通 CLI 默认为 ~/.tlon/.env，自定义 TLON_HOME 同样生效。界面用“当前实例的数据目录”和通用重启提示，不展示 Windows 专属路径或退出指引。

既有配置以当前进程实际使用的服务商环境变量为准（包含启动时从实例 .env 加载的值），沿用 LLMClient 的 provider/model 与 PROVIDER_API_KEY 命名规则。启动时已有至少一位成员的模型具备非空凭据，即视为已有配置，直接进入；不自动请求服务商、不自动改写成员模型。其他未配置成员仍可在设置页单独配置。已有配置或完成标记均撤销整体初始成员范围的授权；后续修复只能明确选择成员或仅更新凭据。

保留完成标记最后写入、失败可重试的行为。不能因本次配置失败前已写入的凭据而跳过剩余成员应用；无标记的既有配置识别在服务构造时完成。凭据存在不代表服务商已验证其有效性，手动配置失效可从设置页重新验证。环境变量仍优先于配置文件；网页明确保存新凭据时更新当前进程和实例 .env。

首次写入凭据前创建 `model-setup.pending`，成功写入完成标记后清理。重启时存在 pending 的实例不得按已有环境凭据跳过未完成的成员应用；首次范围仍可重试。没有模型成员的空实例无需完成向导即可进入，即使留下 pending 也不会要求选择不存在的成员；后续配置成功时清理 pending，避免无法创建成员的死循环。
