# WebUI 设计

WebUI 是浏览器中的人类客户端，由 React + Vite + TypeScript 实现，使用 [REST + SSE 协议](./server-protocol.md)。本文负责页面状态、邮箱同步与交互；邮局事务及已读语义由 [mail.md](./mail.md) 定义，精确端点和字段见 [API reference](../reference/api-reference.md)。邮箱一致性的选择历史见 [ADR 0031](../decisions/0031-webui-mail-consistency.md)。

## 领域约束

- 所有数据与动作经 REST/SSE；浏览器不直接访问 runtime 或成员文件。
- 邮箱与已读以服务端持久快照为权威；SSE 只是实时通知。打开页面、线程或重连不自动标读。
- 本人邮箱可以显式标读，观察其他成员邮箱只读，也不展示他人的 read 状态。
- 线程严格按 `thread_id` 分组，不按主题或参与者猜测合并。回复显式携带父邮件和线程头。
- 页面必须说明尚未加载的历史与缺失引用；最近一页不能伪装成完整线程。
- 发信结果未知不能显示为确定失败，重试必须保留原 request_id 和内容；同键改内容由服务端判冲突。

## 当前结构与状态所有权

[App.tsx](../../apps/webui/src/App.tsx) 持有 REST/SSE 客户端与当前视图，用 React 状态驱动导航，没有独立路由库或全局状态库。视图持有各自页面状态，纯逻辑集中在 `src/lib/`。邮箱同步是需要跨异步操作协调的例外，由 [MailboxController](../../apps/webui/src/lib/mailbox.ts) 持有、通过 `useSyncExternalStore` 交给视图；它不是第二份服务端邮箱事实。

| 模块 | 职责 |
|---|---|
| `client/rest.ts` | HTTP 请求、结构化错误与投信回执 |
| `client/sse.ts` | 会话建立、EventSource、连接状态与重连 |
| `lib/mailbox.ts` | 快照/事件合并、历史分页、标读及过期请求隔离 |
| `lib/threads.ts` | 线程分组、标题、过滤和引用关系 |
| `lib/activity.ts` / `lib/agentLiveStatus.ts` | 事件摘要与成员实时展示 |
| `lib/snapshot.ts` / `lib/sessions.ts` / `lib/logs.ts` | 指标、会话与日志的纯展示逻辑 |
| `views/` | 页面交互与渲染 |
| `styles/tokens.css` | 视觉 token 权威 |

TUI 与 WebUI 各自保有纯逻辑模块，没有跨 app 的共享 workspace 包；二者的传输与渲染环境不同，当前没有为小规模重复引入额外工程层。

## 邮箱同步

### 连接就绪后拉快照

SSE 客户端新建会话并切换所需 mode 后打开 EventSource；只有 `onopen` 才报告 connected。开流失败关闭旧流，从零重建会话，指数退避重连，不能继续复用服务端已清理的 session id。

MailboxController 先订阅 event/status，再读取当前连接状态。每次从未连接转为 connected 都触发同步。初次只拉最近页，并保留 `has_more` / `next_before` 给“加载更早邮件”。重连或手动刷新从最新页向前翻，直到覆盖上次成功快照的最新邮件边界，或到历史末尾；补信可以超过一页。失败不推进成功快照边界，本地发信也不推进该边界。

实时 `mail.delivered` 按本人或被观察成员地址筛选，并按 mail id 去重。通知不携带权威 read，不能用重复通知覆盖已加载同 id 邮件。快照可更新 read；它不是仅用于补不存在的邮件。

### 抵御异步竞态

- 页面切换、controller 停止使用 generation 隔离过期请求，旧邮箱响应不能污染新邮箱。
- 快照使用请求顺序和本地修改版本合并，较早请求不能覆盖较新快照或已确认的本地发送、标读结果。
- 整线程标读返回的全部 id 都记录本地 read override，包括当前尚未加载的历史；稍后到达的实时邮件不能把已确认的已读状态复原为未读。
- 并发 refresh 合并为当前刷新后再执行一次；分页游标不前进时报同步错误，避免无限循环。

这些控制只保护页面交错操作；关闭后重新进入仍以服务端持久状态为准。

## 线程与读写交互

MAIL 是线程列表、信件内容与写信抽屉的组合。线程标题优先取根邮件稳定主题，无主题时取正文摘要；辅以参与者、日期、短线程 id、未读数帮助区分。根邮件未加载时明确提示；引用的父邮件缺失仍展示引用提示。筛选覆盖所有已加载正文，不能声称搜索了全部服务端历史。

本人邮箱显示未读数，提供单封与整线程的已读/未读操作。整线程修改由服务端事务覆盖全部历史，页面不以当前加载集合代替目标集合。观察他人时没有写操作。

写信抽屉支持 To/Cc 地址补全、回复预填、主题与正文。每次打开抽屉生成一个 request_id，提交期间防止重复点击；收到真实回执才加入本地已发邮件并显示服务端 message。拒绝或结果未知时保持表单和键，显示结构化 reason。当前表单仍允许编辑：同键改内容不是新投信，可能被服务端拒绝为幂等冲突；页面关闭后也没有持久待确认队列。结果未知时应原样重试或先查邮箱，不能把新开抽屉当作安全重试。

### 多收件人输入（2026-10-18）

TO 与 CC 使用“已选标签 + 独立搜索输入”，候选选择保存稳定邮件地址，显示姓名与可辨认的地址；两栏各自按地址去重，不改变 To/Cc 邮件头语义。支持按姓名、成员 ID、地址忽略大小写的包含搜索，前缀匹配优先，展示全部匹配并在限高列表内滚动。手填或粘贴完整地址可直接添加；姓名和 ID 必须能唯一匹配通讯录，未完成或有歧义的输入明确提示，不自动取第一个人发送。

支持逗号、分号（含中文标点）及换行分隔粘贴。选择或成功确认地址后收起候选并保留输入焦点，继续输入、点击输入框或按方向键可重新展开；点击字段外部（包括弹窗空白处）也会收起，不影响已选标签。Enter 选中候选或确认完整地址；Tab 正常移动焦点，失焦仅确认明确输入；Escape 先关闭候选；空输入 Backspace 删除最后一个标签。输入法组合期间不选择、不发送；Ctrl/Cmd+Enter 只执行统一投信流程，投信前同步解析两栏草稿，界面地址与提交地址一致。候选使用 combobox/listbox 语义，高亮项自动滚入可见区，标签可独立删除，提交时禁用编辑。

通讯录首次进入、打开写信/回复、手动刷新时重新获取；显示加载和失败状态并提供重试，加载失败不清空已选标签，完整地址输入仍可用。组件使用项目现有 React 依赖实现，不新增国际化、搜索或表单框架；窄屏与短屏延续现有弹窗边界约束。写信弹窗外框固定，表单在独立的内部容器滚动，正文框和按钮始终位于外框内，霓虹装饰不随表单滚动。

## 视觉规范

### 窄屏布局与弹窗（2026-10-18）

桌面保留左侧导航；窄屏将导航放到顶栏下方，使用可横向滚动的单行导航，当前入口保持可见。顶栏与工具栏允许换行，主内容区占满剩余宽度，页面本身不得横向溢出。保留现有霓虹配色、边框、字体与卡片视觉。

邮件、原型、能力和追踪按内容容器宽度切换单栏/多栏；卡片的最小列宽不得超过容器。长说明和正文允许换行，列表摘要可省略；代码、原始 JSON 和宽表格在自己的区域内滚动，技术标识及用户内容不被改写。Agents 状态更新继续保持卡片布局稳定。

身份页、表单与弹窗按包含边框和内边距的尺寸计算；弹窗四周保留间距，限制在动态视口高度内并可纵向滚动，短屏也必须能够访问标题和操作按钮。验证覆盖 320/390/760/900/1440px、短屏、长标识及有数据的详情与弹窗。

### 界面语言（2026-10-18）

WebUI 面向用户的固定文案统一使用英文，覆盖导航、标题、按钮、状态、字段说明、占位提示、校验、操作反馈、空状态与前端生成的错误；HTML 语言声明为英文。不引入国际化框架或语言切换。

技术标识保留原文及大小写，包括成员 ID、地址、模型名、工具名、事件名、错误码、配置键、指标名、路径、环境变量及文件名。用户内容、邮件、成员人格、DSL/JSON、模型输出、日志正文、服务端错误详情与演武报告正文均原样展示。界面标签的大写装饰不得改变这些内容；前端错误说明使用英文并保留底层诊断详情。

### Agents 单一状态与稳定布局（2026-10-18）

成员卡片只在右上角展示服务端 `agent.state`，不区分处理 session 与等待 LLM 返回；`thinking` 使用青色呼吸效果，减少动态效果偏好下关闭动画。删除事件驱动的第二个 THINKING 标签及其瞬时状态跟踪。详情面板复用同一状态展示。

卡片始终预留两行历史信息，分别展示最近 LLM 耗时/模型与工具结果；未收到事件时展示占位。每行不换行，长内容省略并通过悬停查看全文。状态标签预留宽度，操作按钮置于底部，状态切换和历史信息更新不改变卡片高度。

当前采用 cyberpunk 视觉：暗背景、青色主操作、品红危险操作、黄色未读/警示/断连。`styles/tokens.css` 集中定义颜色、字体、边框和 glow；视图样式分文件维护。面板使用深色底、细霓虹边框与 HUD 角标，小圆角；标签与指标采用等宽排版，日志/事件保持终端面板语义。具体 token 数值以样式文件为准，不在文档再维护一份 CSS。

## 托管与访问边界

开发使用 Vite dev proxy；生产构建写入 `apps/webui/dist/`，dream 同一 HTTP 端口托管于 `/ui/`，`/ui` 重定向。无构建产物时不注册静态路由，启动 banner 提供构建提示。运行操作见 [快速开始](../guides/quickstart.md)。

WebUI 采用本地单人身份设置（[ADR 0033](../decisions/0033-local-webui-identity.md)）：启动先查询 `/identity`，未设置时填写 username，保存到实例 `{TLON_HOME}/webui-identity.json`；已设置自动进入。身份不再来自 URL 或 localStorage，无密码、登录会话或 admin token。所有 API fetch 带 `X-Tlon-WebUI: 1`，原生 EventSource 由同源 Fetch Metadata 校验；生产 `/ui/` 与 API 同源，开发继续走 Vite 代理，拒绝跨域来源。固定地址是普通 member 地址，不向 agents 添加特殊身份信息。完整来源边界见 [server-protocol.md](./server-protocol.md)。

### 人格文件查看与编辑

成员创建与编辑表单展示 IDENTITY.md（自我定义）、SOUL.md（价值观、性格、表达与判断倾向）、RULES.md（工作规则、流程与明确约束），分工见 [identity](identity.md)。编辑表单先读取三个文件的当前全文与模型；读取失败时禁止保存。保存只提交改动字段，清空文本表示清空对应文件，未改字段不覆盖。人类可编辑三者，成员自主修改仍限于 IDENTITY/SOUL。
