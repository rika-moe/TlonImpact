# Agent 持续主历史

状态：已接受，尚未实施。决策见 [ADR 0048](../decisions/0048-continuous-agent-history.md)，施工见[分阶段计划](continuous-agent-history-plan.md)。本文描述目标语义，不是当前 API 承诺。

## 当前实现与目标边界

当前 `tlon.agent/respond` 每次调用 member-context，拼接知识、经验、技能、任务、recap、近期邮件和本次邮件；返回的 messages 不作为下次入口的起点。`tlon.conversation`、`tlon.messages` 和 `tlon.context` 已将消息处理表达为普通函数。ProgramStore 已有私有 state，state-put 与自身 invocation 回执原子提交；complete_entry 只原子提交入口结果、完成与调度，不包含任意私有状态。

目标是同一 Agent 的所有收件按成员串行受理顺序进入一段主历史，包括不同发件人和主题。抄送、批量积压邮件也按实际受理顺序进入，不按邮件时间戳回插。重复事件依 mail ID 和原运行身份去重；新邮件不能再从 mail_history 重复导入。启动前已存在的邮箱不自动迁入；首个执行建立主历史，积压未读邮件由正常事件受理。其他事件需要模型工作时使用同一程序入口约定，不另建隐藏历史；纯维护反思/蒸馏保持独立根，不直接写主历史。

| 所属 | 职责 |
|---|---|
| 普通 module | 追加、保存点、压缩、计划和核验策略，以及从回执补齐工作视图 |
| ProgramStore / OperationExecutor | 私有状态、原调用身份、原始结果、预算、未知结果与事务原子性 |
| MemberRuntime | 串行事件、冻结本次程序包、恢复、完成与调度；只补齐必要的状态/身份事实访问 |
| 交互投影 | 只读核对与查询，不是第二套恢复日志 |

共享主历史约束的是跨事件工作记录，不是所有模型请求的形状。Agent 可自由编写循环、分支、计划、核验及其调用顺序，也可只选取相关材料构造临时模型请求，再将实际采用的结果及来源追加到主历史。标准库函数可选，不强制所有 workflow 经同一对话循环或历史管理函数；宿主仅保障执行事实、恢复、消息协议与资源边界。

不新增 Session 对象、会话执行器、后台永久模型循环或独立历史数据库。主历史放在现有成员 ProgramStore 的普通私有状态中；首版整体保存 JSON 值，不先引入分片、索引或独立存储服务。程序拥有的历史键不向模型提供任意改写入口，模型使用普通工具维护的 CONTACTS.md 等笔记仍独立存在。

## 持久状态与保存点

普通状态至少表达：当前可发送的 messages、关联的事件/运行身份、未完成交互的证据引用、有效提示配置快照，以及必要的压缩来源范围。它们是程序数据，不定义新的宿主会话生命周期枚举。每个检查点带来源运行和单调修订号，避免重放旧写覆盖后续历史；宿主绑定当前调用身份，不相信模型传入的 run_id。当前 state API 是否足以完成条件写和回执回查，要在首阶段核实，不把缺失能力写成已有保证。

可发送历史只包含协议完整的消息。尚待执行或结果未补齐的 assistant/tool_calls 作为待完成数据保存，不作为下一次模型输入。保存点如下：

1. 受理邮件：原事件已持久冻结，读到的历史基线作为本次已记录读取；追加一次带发件人、收件人、邮件 ID 和内容的输入，保存后再请求模型。
2. 模型返回普通文本：保留实际响应和来源；在下一次模型请求或外部写入前保存。计划和核验也遵循此边界。
3. 模型返回工具调用：先保存原始响应、调用顺序与待执行状态，再执行工具。全部结果已知后，按原顺序追加一个完整 assistant/tool 组并保存，然后才允许下次模型请求。部分工具成功的事实留在原回执中。
4. 事件外层自动发信、标读：同样先记录待执行动作，完成后保存真实结果与引用。宿主投递结果不能伪造成模型曾发出的 tool_call；以明确标注的工作事实追加。标读与历史保存各自有幂等回执，不构成一个虚构的跨域事务。
5. 入口返回：必须没有未解释的交互或投递结果。入口完成不清除历史；保存检查点与完成不强求一个大事务，依同一运行恢复闭合二者之间的窗口。

计划、评审及压缩可以有临时分支请求。主历史保存实际采用的内容及其来源和性质；不能把支线结果伪装成主模型原始响应。评审修改工具参数时保留原建议和实际执行参数，不能重写原响应。延续主历史时不能无意丢弃已发生的压缩而退回旧 history；核验等临时请求可按工作程序选取相关材料。无论请求是否携带完整历史，实际采用结果与执行事实都须按来源保存。

## 失败与恢复

既有冻结源码、确定调用路径、Operation 回执和模型账本仍是恢复权威。恢复读取原事件记录及原 state-get 结果；不能读当前历史重新追加同一封邮件。恢复到已提交 state-put 时返回原回执，不重新覆盖历史。主历史推进只允许一个所有者；其他普通程序不得同时改写该键。

| 故障窗口 | 处理 |
|---|---|
| 邮件已保存，模型尚未调用 | 原运行继续，邮件不重复追加 |
| 模型响应已提交，历史尚未保存 | 从原模型回执恢复响应，不重复请求或扣费 |
| 工具部分/全部完成，完整组尚未保存 | 依原调用身份补齐已提交结果；仅按既有 retry_safe 契约继续未决调用，绝不重发不安全写入 |
| 历史已保存，入口尚未完成 | 重放原保存回执，继续剩余动作与完成提交 |
| 明确失败、预算/fuel 耗尽 | 保留最后完整历史和原回执；补齐确定结果并追加失败事实后，后续事件可用自己的预算继续 |
| 模型/不安全写入 unknown、身份失配、证据缺失 | 保留待完成信息和最后完整历史，阻止后续事件推进这段主历史，诊断上浮；不伪造失败结果或重开根绕过 |
| 历史状态损坏或格式不支持 | 隔离、保留原字节与回执并报错，不当作空历史重新开始 |

确定失败后的补齐只读取回执、做确定性转换和持久保存，不调用模型，也不借新根补做旧效果。它是普通程序的恢复整理逻辑；若冻结程序损坏或证据不足则阻塞，不能用当前新版程序猜测解释旧记录。需要的运行终态和叶子引用优先复用现有只读投影，确实缺失时仅补通用只读事实访问，不新造工作流解释器。

unknown 对其他独立根的隔离语义保留，但所有后续邮件共享主历史，因此不能绕过该历史的未决所有者。新邮件继续持久入箱、保持未处理，待原调用按既有契约对账或操作员依据外部证据明确处置。不能用“换一个事件预算”消除未知。正常失败则在完成上述确定性整理后释放推进权。

操作员先备份记录，再核实原调用和外部效果；只有有证据的处置才能解除阻塞。首版不提供强制重发、清空历史或绕过 unknown 的按钮。进程退出、取消和休眠不代表外部效果回滚；持久历史本身不计入 active_session_count。

## 独立事件预算与事件顺序

每次事件受理生成独立 run_id、fuel 和冻结预算契约；上一事件未消费的额度不转入下一事件，下一事件不补充旧根。计划、评审、工具内模型和压缩均计入本事件根；维护仍使用独立维护根。缓存命中不能被解释为零额度消费，账本继续按现行 output/total 口径结算。

成员串行执行。正在处理 A 时，B 先入箱排队，不插入 A 的在途模型请求或半个工具组。A 完成或明确失败并整理后才受理 B；A unknown 则按前述规则阻塞主历史。完成事件即可等待、排空或休眠，唤醒后继续持久历史，不维持长驻求值器。邮件标读与是否已经给发件人成功投递仍是独立事实。

## 压缩

默认只追加；不按邮件数、每次入口或资料变动重建前缀。每次模型请求前用实际冻结系统、工具和预留输出估算窗口，预留一轮模型与工具交换的空间；空间不足时对一批旧的完整组做压缩，留下稳定前缀、本次待完成任务与最近完整交换。具体余量作为标准程序策略确定，不新增宿主配置体系。

摘要保留邮件/运行来源、承诺、待办、已知结果、失败与不确定性；摘要不是执行回执。原始回执和邮件不删除，缺失细节可普通查询回读。压缩调用受当前预算约束，成功后原子保存新的工作视图和覆盖来源范围，后续事件沿用，不逐次重新总结同一范围。

压缩过程中失败，旧视图保持；已提交摘要响应恢复时直接复用。压缩后仍不合法、单个不可拆交互组过大、或预算不足时明确失败，不能静默截断工具组、丢掉当前邮件或换根重试。压缩是允许改变前缀的明确边界；实施要验证批量压缩后能容纳后续交换，避免刚压缩完就再次压缩。

## 配置变更：优先保持追加

主历史初始化时固定有效系统提示、工具定义顺序与内容，以及非秘密模型请求配置；每个新事件把这份有效快照冻结进自己的运行包。当前配置文件不是每封邮件重新生成 system/tools 的理由。新到的资料、任务变化和核验意见按需读取并追加，不回写历史开头。

| 变化 | 生效语义 |
|---|---|
| 联系簿、知识、经验、任务内容 | 按需读取并追加带来源的新事实，旧事实由追加纠正，不全文重新注入 |
| 人格、系统说明、工具目录或 schema、模型/请求参数 | 标记待生效，只有显式应用后才在下一个事件边界使用；保留消息历史，并追加变更说明 |
| 权限撤销、安全限制 | 立即约束真实执行；冻结目录不授予权限。受影响调用明确拒绝，不偷偷换目录；管理员可显式应用新目录 |
| 凭据轮换、传输连接 | 使用当前有效凭据，不在历史或冻结包保存秘密；不能据此隐式改模型或请求语义 |
| 事件预算、截止与装置资源限制 | 按当前事件受理冻结，受当前授权限制；不继承主历史的旧额度 |
| 宿主/模块源码升级 | 旧 pending 仍按原构建/冻结包恢复，不兼容即阻塞；新事件采用已批准程序，不因此清空主历史或重建前缀 |

显式应用是人类可检查的配置操作，不是模型自治热更新入口。首版复用现有配置/管理通道，只补必要的生效语义和有效/待生效差异展示，不另建配置平台。应用失败保留旧有效快照和待生效差异并报告原因，不将失败伪装成成功。

更换模型或工具时先验证历史协议与窗口；可以在明确操作中压缩旧完整组并保留来源，接受一次必要的前缀变化。无法合法承载则拒绝应用；不自动丢弃历史、合成工具成功结果或提供跨版本兼容。普通追加期间不得为核验或返回值改写既有消息；受控压缩和显式配置应用是例外。

## 验收证据与非目标

确定性测试比较相邻事件的真实序列化请求：无压缩和配置应用时，同一调用用途的系统/工具不变，主 messages 只追加；核验支线使用自己的合法工具集，不能为缓存向核验模型多授权。恢复逐窗口断言调用次数、预算账本、历史字节与实际投递数。真实冒烟跨至少三封邮件、一次重启、一次文件资料修改，证明连续历史及新事实可见；另测压缩和显式配置应用。

记录 provider 返回的 cached/input token、总输入、压缩消耗及正确性，不以单次高命中或保证百分比验收；provider 未提供缓存字段时明确未知。无需为了引用缓存产品规则引入 provider 专有能力。

不包含多历史路由、会话状态图、事件抢占、自动换模型、模型自行改执行回执或行为源码热更新。不同发件人的输入保留来源与信任边界；主历史共享不意味着允许把私有材料转发给其他人。
