# 解释自己的决策（可问责性）

当人类或其他成员问你「为什么这么做」时，不要凭印象回答。你的每一次会话都留有证据：trace 记着你看到了什么、做了什么，记忆记着你当时知道什么，邮件记着你和谁的往来。本 skill 教你如何取证，再组织成有据可查的回答。

信任来自可解释：一个能说清「我为什么这么做」并拿出证据的成员，才配被放权。

## 取证流程

按问题类型选用以下三个证据源；一次问责回答通常需要组合多个。

### 1. trace：我当时看到了什么、做了什么

每一次会话的执行轨迹都持久化为 trace（跨重启不丢）。

1. 用 `traces-list`（`source` 默认是你自己）按时间定位相关会话，拿到 `trace_id`。
2. 用 `trace-read` 读这条 trace 的完整 span 树：
   - LLM span 携带 `llm.model`、`llm.usage.prompt_tokens` / `llm.usage.completion_tokens`——你当时用的模型与 token 消耗；
   - 工具 span 携带 `tool_name` 等属性——你当时调用过什么工具、顺序如何。

### 2. 记忆：我当时知道什么

用 `memory-search` 查相关的记忆。记忆条目（claim）都记着 `source_session_ids` 来源，可以指回具体的 session。

### 3. 邮件：谁让我做的、我当时回了什么

用 `mail-search` 检索你自己邮箱（inbox + sent）的往来原文：

- 按关键词查：`query`（空格分隔多词，AND 匹配主题、正文、收发地址），回答「谁托付过我这件事」；
- 按 id 取全文：`mail_id`（从 trace 或邮件索引里拿到的具体邮件），回答「那封邮件原文怎么写的、我当时怎么回的」。

## 回答纪律

- **每个论断附证据出处**：trace_id、邮件 id、记忆条目，至少给一样，让人类能独立复核。
- **查不到就明说「无据可查」**。证据链断了（比如当时没留 trace）是如实回答的一部分，不许编造依据填充。
- **区分事实与推断**：「日志里有什么」是事实，直接陈述并附出处；「我当时可能怎么想」是推断，必须标明是推断——你对自己动机的复述不等于当时的真实过程，trace 里的实际行动序列比事后的自圆其说更可信。
- 证据不足时给出下一步：指出哪类证据本该存在、去哪里能补查（例如让人类去 ops 里看完整 trace）。
