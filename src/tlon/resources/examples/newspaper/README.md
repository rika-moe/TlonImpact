# 来信报：普通成员的 DSL 工作流

此目录是可复制的成员示例，不会在首装或升级时自动创建报社，也不修改现有成员。`behavior.tlon` 包含全部办报业务；Python runtime 只提供通用状态、模型和邮件效果。

通过正常成员创建流程使用此行为文件，再配置成员级 `llm.model_name`（例如 `deepseek/deepseek-v4-flash`）和 provider 凭证。把三个 Markdown 文件作为该成员的身份、价值取向和约束。执行级别为 L0，不需要设备沙箱。

**启用前把行为文件中的 `operator@tlon.internal` 改为实际管理员邮箱。** 这只是示例的明确授权名单，不会自动授予任何地址管理员权限。

| 邮件主题 | 行为 |
| --- | --- |
| `subscribe` | 发件地址订阅；忽略正文中的代订要求 |
| `unsubscribe` | 发件地址退订；不影响已经冻结的期刊 |
| `submit` | 按真实邮件 ID 收稿，保存发件人和原文 |
| `publish:2026-10-18` | 管理员出版指定期号；相同期号重试复用冻结版本 |

主题区分大小写，不去除空格。其他邮件不产生业务操作。处理结束显式标为已读；已读标记不是进度记录。出版不自动定时；已有 cron 可给报社发送明确期号的出版邮件。

订阅、稿件和每一期冻结版本保存在成员私有的 `program.sqlite3`。空期不调用模型、不寄报纸；该期号会冻结为空期，新稿应使用新期号。新一期只收录尚未入刊的稿件。模型输出为空或全空白时不冻结、不投递，可重新发出版命令再试。

每份报纸附真实投稿邮件 ID，正文由模型编辑，来源附录由 DSL 拼接。这个约束保证来源编号可追溯，**不保证摘要中的每一句都真实**。原始稿件可按邮件 ID 从邮箱核查，不能把模型编辑当成事实审核。

分发按冻结时的订阅名单逐人执行。稳定请求 ID 为 `edition:<期号>:<地址>`，邮局幂等提交覆盖入箱后程序日志尚未写入的崩溃窗口。接受回执会记录到期刊；新出版命令跳过已经成功的地址。拒收不记成功；结果未知时不推进分发成功标记，可用相同期号重新发送出版命令，继续复用冻结正文及原 request_id。进程崩溃后的程序重放复用已经记录的效果，邮局回执覆盖已提交但效果结果未记录的窗口。外部邮件网关仍沿用现有的尽力投递语义。

这是最小案例：没有网页订阅、稿件审核队列、自动事实核查、跨站转载或无限期保存策略。生产使用前应补充适合办报场景的留存与审核规则。
